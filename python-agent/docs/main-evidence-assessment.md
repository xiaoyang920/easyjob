# 检索充分性与下一步动作合并

知识检索执行查询改写（可跳过）、BM25/KNN、RRF、Reranker 和来源可见性/内容版本检查后，直接把候选正文与引用交回 Main。检索后不再固定调用独立的相关性/充分性 LLM。

`retrieval_report.assessment_owner=main` 表示语义判断由下一轮 Main 完成。报告只记录平台/联网是否请求、被阻止、返回候选、为空、失败，以及精排是否降级；`succeeded`/`found` 不代表候选相关或资料充分。条件解析失败保留原过滤范围，不扩大权限。

Main 在一次 `MainDecision` 调用中同时输出：

- `evidence_assessment.selected_ids`：真正相关、可使用的原始引用 ID。
- `adequacy`：全部所选资料相对用户整体目标是 `sufficient`、`partial` 还是 `none`。
- `reason` 与 `missing_aspects`：判断原因及尚缺内容。
- `action`：直接回答、针对缺口继续检索、委派或进入草稿审批流程。

例如已有 Cache Aside 原理但缺少删除失败补偿时，Main 同时选出原理引用、标记 `partial`，并生成补偿方向的新查询。没有新增“评估”动作，不需要先评估再调用另一个 Main。判断为部分充分也可以交付已知部分，明确限制。

后端验证所选 ID 来自成功任务；回答时必须属于声明的回答依赖。重复 ID、伪造 ID、充分性与空选择矛盾会进入已有的一次格式修正边界。最终答案和卡片只交付被选中且正文实际引用的来源；主代理产物和草稿仅继承所选证据。所有原始检索结果仍保留，后续 Main 可以重新判断和复用，旧结果不被覆盖。

重复动作指纹、工具故障限次重试、轮数/任务数/超时限制及最终来源版本验证继续生效。降级回答只能复用已经选择的来源，不能把尚未评估的候选自动当成相关资料。旧检查点中的独立评估结果保留兼容读取，但新的结果不再写 `quality.adequacy`。

每次有候选的知识检索正常路径减少一次固定 LLM 评估调用；查询改写、引用错误或格式错误的限次修正仍可能调用模型。充分性是模型判断，并不保证事实绝对正确。离线测试验证调用次数和执行契约，不作为真实模型质量或延迟成绩。

在 `python-agent` 下配置离线假密钥后运行 `python -m unittest discover -s tests`。真实本地语料的精排故障测试可显式运行 `scripts/retrieval-degradation-check.py`，会调用配置的模型；它只执行一次新的 Main 决策，不执行其返回的后续检索或草稿动作。
