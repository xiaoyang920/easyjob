## 阶段一：统一模型管理 + 实现 Writing/Analysis Worker

### 1.1 用 `init_chat_model` 替换硬编码（最新 API）

**你会学到**：LangChain 最新的模型初始化方式，一行代码切换任意 Provider。

**现状问题**：每个节点都重复写一遍 `ChatOpenAI(model=..., api_key=..., base_url=...)`。

**改造 `config.py`**：

```python
"""
config.py — 统一模型管理
"""
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model  # 2025 新 API

load_dotenv()


class Settings:
    # ... 原有配置不变 ...
    
    DEEPSEEK_API_KEY: str = os.getenv("DEEPSEEK_API_KEY", "")
    DEEPSEEK_BASE_URL: str = os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com/v1")
    
    # ... 其他配置 ...


settings = Settings()


def get_llm(temperature: float = 0.7, **kwargs):
    """
    统一获取 LLM 实例。
    
    用 init_chat_model 替代到处写 ChatOpenAI()。
    好处：
    1. 切换模型只需改这一个地方
    2. init_chat_model 支持 "openai:gpt-4o"、"anthropic:claude-xxx" 等统一格式
    3. 当前我们用 DeepSeek（OpenAI 兼容），所以直接用 ChatOpenAI provider
    """
    return init_chat_model(
        model="deepseek-chat",
        model_provider="openai",       # DeepSeek 兼容 OpenAI 协议
        api_key=settings.DEEPSEEK_API_KEY,
        base_url=settings.DEEPSEEK_BASE_URL,
        temperature=temperature,
        **kwargs,
    )
```

**然后所有节点统一改为**：

```python
from app.config import get_llm

async def chat_worker_node(state: AgentState) -> dict:
    llm = get_llm()           # 一行搞定，不再重复写配置
    # ... 后续逻辑不变 ...
```

> **学习要点**：`init_chat_model` 是 LangChain 2025 年推荐的统一模型初始化 API，支持 `"openai:gpt-4o"`、`"anthropic:claude-sonnet-4-6"` 等格式，一行代码切换 Provider，无需手动 import 各种 `ChatXxx`。

### 1.2 实现 Writing Worker（学习 Tool Calling 循环）

**你会学到**：完整的 LangChain Tool Calling 循环模式——LLM 决策 → 执行工具 → 结果回传 → 再次调用 LLM。

**新建 `app/graph/nodes/writing_worker.py`**：

```python
"""
Writing Worker 节点
实现写作/内容创作功能，支持 LLM 自主决策是否需要搜索参考资料。

【学习重点】
1. @tool 装饰器：定义 LLM 可调用的工具
2. bind_tools()：告诉 LLM 有哪些工具可用
3. Tool Calling 循环：LLM 决策 → 执行 → 回传 → 再决策（最多 N 轮）
4. ToolMessage：工具执行结果的标准消息格式
"""
from langchain_core.messages import SystemMessage, HumanMessage, ToolMessage

from app.config import get_llm
from app.graph.state import AgentState
from app.tools.web_search import web_search
from app.tools.article_tool import search_articles, search_articles_by_knn


# 工具映射表：name → function，用于根据 LLM 返回的工具名找到对应函数
tool_map = {
    "web_search": web_search,
    "search_articles": search_articles,
    "search_articles_by_knn": search_articles_by_knn,
}

# 可用工具列表
available_tools = [web_search, search_articles, search_articles_by_knn]

# 最大工具调用轮数（防止无限循环）
MAX_TOOL_ROUNDS = 2


WRITING_SYSTEM_PROMPT = """你是一个专业的技术写作助手。

【职责】
- 根据用户需求撰写高质量的技术文章、博客、教程
- 如果需要引用数据或案例，使用工具搜索参考资料
- 文章结构清晰，内容准确，语言专业

【可用工具】
- search_articles：搜索平台内已有的技术文章
- search_articles_by_knn：基于语义向量搜索平台文章
- web_search：联网搜索最新信息

【工具使用原则】
1. 先评估是否需要参考资料，简单创作不需要搜索
2. 需要数据支撑、引用案例时，优先用 search_articles
3. 需要最新信息时，用 web_search
4. 最多调用 2 轮工具，然后必须给出最终结果
"""


async def writing_worker_node(state: AgentState) -> dict:
    """
    写作 Worker：支持 LLM 自主调用工具获取参考资料

    【Tool Calling 循环流程】
    1. LLM 收到任务 + 工具列表
    2. LLM 决定：直接回答 or 调用工具
    3. 如果调用工具 → 执行工具 → 结果作为 ToolMessage 回传
    4. LLM 基于工具结果继续决策（最多 MAX_TOOL_ROUNDS 轮）
    5. 最终 LLM 给出写作结果
    """
    task_input = state["task_descriptions"].get("writing", state["user_message"])

    # 获取 LLM 并绑定工具
    llm = get_llm()
    llm_with_tools = llm.bind_tools(available_tools)

    # 构建初始消息
    messages = [
        SystemMessage(content=WRITING_SYSTEM_PROMPT),
        HumanMessage(content=f"写作任务：{task_input}"),
    ]

    # ============== Tool Calling 循环 ==============
    # 这是 LangChain 工具调用的核心模式，务必理解
    for round_num in range(MAX_TOOL_ROUNDS):
        # Step 1: 调用 LLM（LLM 会决定是否调用工具）
        response = await llm_with_tools.ainvoke(messages)

        # Step 2: 检查 LLM 是否决定调用工具
        if not response.tool_calls:
            # LLM 决定不调用工具，直接输出最终结果
            break

        # Step 3: LLM 决定调用工具 → 把 LLM 的响应（含 tool_calls）加入消息列表
        messages.append(response)

        # Step 4: 逐个执行工具，把结果作为 ToolMessage 加入
        for tool_call in response.tool_calls:
            tool_name = tool_call["name"]
            tool_args = tool_call["args"]
            tool_fn = tool_map.get(tool_name)

            if tool_fn:
                tool_result = await tool_fn.ainvoke(tool_args)
            else:
                tool_result = f"工具 {tool_name} 不存在"

            # ToolMessage 必须带上 tool_call_id，LLM 靠它匹配请求和结果
            messages.append(ToolMessage(
                content=tool_result,
                tool_call_id=tool_call["id"],
            ))

        # 循环回到 Step 1，LLM 基于工具结果继续决策
    else:
        # 达到最大轮数，强制让 LLM 输出最终结果（不再绑定工具）
        response = await llm.ainvoke(messages)

    return {
        "worker_results": [{
            "worker_name": "writing",
            "result": response.content,
        }]
    }
```

**更新 `builder.py`**，替换占位函数：

```python
# builder.py
from app.graph.nodes.writing_worker import writing_worker_node

# 删除占位函数 writing_worker_node
# 把 graph.add_node("writing_worker", ...) 改为：
graph.add_node("writing_worker", writing_worker_node)
```

> **学习要点**：
> - `bind_tools([...])` 不会自动执行工具，它只是告诉 LLM "你可以调用这些工具"
> - LLM 返回 `response.tool_calls` 列表，你需要自己执行工具并把结果放回消息列表
> - `ToolMessage` 的 `tool_call_id` 必须和 `tool_call["id"]` 对应，否则 LLM 无法匹配
> - 循环次数要有上限（`MAX_TOOL_ROUNDS`），防止 LLM 无限调用工具

### 1.3 实现 Analysis Worker（学习纯 LLM 推理节点）

**你会学到**：不是所有节点都需要 Tool，有些节点只需要 LLM 推理 + 结构化输出。

**新建 `app/graph/nodes/analysis_worker.py`**：

```python
"""
Analysis Worker 节点
纯 LLM 推理，不需要工具调用。

【学习重点】
1. 并非所有节点都需要 Tool Calling
2. 使用 with_structured_output 让 LLM 返回结构化数据
3. worker_results 的 Annotated[list, add] reducer 如何自动合并并行结果
"""
from pydantic import BaseModel, Field
from langchain_core.messages import SystemMessage, HumanMessage

from app.config import get_llm
from app.graph.state import AgentState
from app.tools.article_tool import search_articles, search_articles_by_knn
from app.tools.web_search import web_search
from langchain_core.messages import ToolMessage


tool_map = {
    "search_articles": search_articles,
    "search_articles_by_knn": search_articles_by_knn,
    "web_search": web_search,
}

available_tools = [search_articles, search_articles_by_knn, web_search]


ANALYSIS_SYSTEM_PROMPT = """你是一个数据分析专家。

【职责】
- 对给定的主题进行深入分析
- 如果手头没有足够的数据，可以调用工具搜索相关资料
- 输出结构化的分析结果：趋势、对比、建议

【可用工具】
- search_articles：搜索平台内已有的技术文章
- search_articles_by_knn：基于语义搜索平台文章
- web_search：联网搜索最新数据

【分析要求】
- 使用数据和事实支撑观点
- 提供对比表格或列表
- 给出可操作的建议
"""


async def analysis_worker_node(state: AgentState) -> dict:
    """
    分析 Worker：先搜索数据，再进行 LLM 分析推理。

    注意：由于 LangGraph 的 Send API 并行执行 worker，
    analysis_worker 和 search_worker 是同时运行的，
    所以 analysis_worker 不能依赖 search_worker 的结果。
    它需要自己调用工具获取数据。
    """
    task_input = state["task_descriptions"].get("analysis", state["user_message"])

    llm = get_llm()
    llm_with_tools = llm.bind_tools(available_tools)

    messages = [
        SystemMessage(content=ANALYSIS_SYSTEM_PROMPT),
        HumanMessage(content=f"分析任务：{task_input}"),
    ]

    # 最多 2 轮工具调用收集数据
    for _ in range(2):
        response = await llm_with_tools.ainvoke(messages)
        if not response.tool_calls:
            break

        messages.append(response)
        for tool_call in response.tool_calls:
            tool_fn = tool_map.get(tool_call["name"])
            if tool_fn:
                result = await tool_fn.ainvoke(tool_call["args"])
            else:
                result = f"工具 {tool_call['name']} 不存在"
            messages.append(ToolMessage(
                content=result, tool_call_id=tool_call["id"]
            ))
    else:
        response = await llm.ainvoke(messages)

    return {
        "worker_results": [{
            "worker_name": "analysis",
            "result": response.content,
        }]
    }
```

> **学习要点**：
> - 并行 Worker 之间**不能互相依赖**结果（Send API 同时执行）
> - 每个 Worker 应该是**自给自足**的，需要数据就自己调工具
> - `worker_results: Annotated[list, add]` reducer 保证并行 Worker 的结果**自动累加**不覆盖

## 阶段二：Checkpointer 持久化 + 长期记忆

### 2.1 Redis Checkpointer——真正的多轮对话（最新 API）

**你会学到**：LangGraph 的 Checkpointer 机制——自动保存/恢复图的每一步状态。

**这是 LangGraph 最强大的能力之一**：你不需要手动管理对话历史，Checkpointer 会自动把每一轮的完整状态存入 Redis，下次调用时自动恢复。

**安装依赖**：

```bash
pip install langgraph-checkpoint-redis
```

**更新 `requirements.txt`**：

```
langgraph-checkpoint-redis>=0.1,<1.0
```

**改造 `builder.py`**：

```python
"""
builder.py — 加入 Redis Checkpointer
"""
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.redis.aio import AsyncRedisSaver  # 异步版本

from app.config import settings
from app.graph.state import AgentState
from app.graph.nodes.planner import planner_node
from app.graph.nodes.dispatcher import dispatcher_node
from app.graph.nodes.search_worker import search_worker_node
from app.graph.nodes.chat_worker import chat_worker_node
from app.graph.nodes.writing_worker import writing_worker_node
from app.graph.nodes.analysis_worker import analysis_worker_node
from app.graph.nodes.synthesizer import synthesizer_node


def _build_graph() -> StateGraph:
    """构建图结构（不含 checkpointer）"""
    graph = StateGraph(AgentState)

    graph.add_node("planner", planner_node)
    graph.add_node("search_worker", search_worker_node)
    graph.add_node("chat_worker", chat_worker_node)
    graph.add_node("analysis_worker", analysis_worker_node)
    graph.add_node("writing_worker", writing_worker_node)
    graph.add_node("synthesizer", synthesizer_node)

    graph.add_edge(START, "planner")
    graph.add_conditional_edges("planner", dispatcher_node)

    graph.add_edge("search_worker", "synthesizer")
    graph.add_edge("chat_worker", "synthesizer")
    graph.add_edge("analysis_worker", "synthesizer")
    graph.add_edge("writing_worker", "synthesizer")

    graph.add_edge("synthesizer", END)
    return graph


def create_agent_graph():
    """无 Checkpointer 版本（向后兼容）"""
    return _build_graph().compile()


async def create_agent_graph_with_memory():
    """
    带 Redis Checkpointer 的版本

    【核心概念】
    - Checkpointer 在每个节点执行后自动保存 state 快照
    - 下次调用同一个 thread_id 时，自动恢复上次的 state
    - 支持 get_state() 查看任意时刻的状态
    - 支持 get_state_history() 查看完整状态历史

    【thread_id 的作用】
    - 每个对话会话有一个唯一的 thread_id
    - 同一个 thread_id = 同一个对话上下文
    - 不同 thread_id = 完全独立的对话
    """
    redis_url = f"redis://{settings.REDIS_HOST}:{settings.REDIS_PORT}/{settings.REDIS_DB}"

    # AsyncRedisSaver 是异步上下文管理器
    checkpointer = AsyncRedisSaver.from_conn_string(redis_url)
    await checkpointer.asetup()  # 首次使用需要初始化

    return _build_graph().compile(checkpointer=checkpointer), checkpointer
```

**改造 `main.py`**：

```python
"""
main.py — 支持 Checkpointer 的版本
"""
import json
from contextlib import asynccontextmanager

from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from pydantic import BaseModel, Field

from app.graph.builder import create_agent_graph_with_memory
from app.graph.state import AgentState


# ========== 应用生命周期管理 ==========

compiled_graph = None
redis_checkpointer = None


@asynccontextmanager
async def lifespan(app: FastAPI):
    """FastAPI 生命周期：启动时创建图，关闭时清理资源"""
    global compiled_graph, redis_checkpointer
    compiled_graph, redis_checkpointer = await create_agent_graph_with_memory()
    yield
    # 清理资源（如果需要）


app = FastAPI(title="EasyJob Python Agent", lifespan=lifespan)


class ChatRequest(BaseModel):
    user_id: int
    conversation_id: int | None = None
    message: str
    # history_messages 不再需要！Checkpointer 自动管理
    # history_messages: list[dict] = Field(default_factory=list)


class ChatResponse(BaseModel):
    reply: str
    conversation_id: int


@app.get("/health")
def health_check():
    return {"status": "ok"}


@app.post("/chat", response_model=ChatResponse)
async def chat(request: ChatRequest):
    """
    带 Checkpointer 的聊天接口

    【关键变化】
    1. 不再需要前端传 history_messages
    2. 通过 thread_id 关联对话上下文
    3. LangGraph 自动保存和恢复状态
    """
    conversation_id = request.conversation_id or request.user_id

    initial_state: AgentState = {
        "user_message": request.message,
        "history_messages": [],  # Checkpointer 会自动恢复历史
        "active_workers": [],
        "task_descriptions": {},
        "worker_results": [],
        "final_reply": "",
    }

    # thread_id 是 Checkpointer 的核心概念
    # 同一个 thread_id → 同一个对话上下文
    config = {
        "configurable": {
            "thread_id": f"conversation_{conversation_id}"
        }
    }

    result = await compiled_graph.ainvoke(initial_state, config=config)

    return ChatResponse(
        reply=result["final_reply"],
        conversation_id=conversation_id,
    )


@app.post("/chat/stream")
async def chat_stream(request: ChatRequest):
    """流式聊天（带 Checkpointer）"""
    conversation_id = request.conversation_id or request.user_id

    initial_state: AgentState = {
        "user_message": request.message,
        "history_messages": [],
        "active_workers": [],
        "task_descriptions": {},
        "worker_results": [],
        "final_reply": "",
    }

    config = {
        "configurable": {
            "thread_id": f"conversation_{conversation_id}"
        }
    }

    async def generate():
        async for event in compiled_graph.astream_events(
            initial_state, config=config, version="v2"
        ):
            if event["event"] == "on_chat_model_stream" \
                    and event["metadata"].get("langgraph_node") == "synthesizer":
                chunk = event["data"]["chunk"].content
                if chunk:
                    yield f"data: {json.dumps({'content': chunk})}\n\n"
        yield "data: [DONE]\n\n"

    return StreamingResponse(generate(), media_type="text/event-stream")


# ========== 新增：查看/删除对话状态 ==========

@app.get("/conversation/{conversation_id}/state")
async def get_conversation_state(conversation_id: int):
    """
    查看对话状态（Checkpointer 的调试能力）

    这就是 Checkpointer 的强大之处：
    你可以随时查看某个对话的完整状态快照
    """
    config = {"configurable": {"thread_id": f"conversation_{conversation_id}"}}
    state = await compiled_graph.aget_state(config)
    if state.values:
        return {
            "conversation_id": conversation_id,
            "state": {
                "user_message": state.values.get("user_message", ""),
                "final_reply": state.values.get("final_reply", ""),
                "active_workers": state.values.get("active_workers", []),
            }
        }
    return {"conversation_id": conversation_id, "state": None}


if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

### 2.2 Long-term Memory——跨会话的用户记忆（最新 Store API）

**你会学到**：LangGraph 2025 新增的 `Store` API，实现跨会话的长期记忆。

**Checkpointer vs Store 的区别**：

| | Checkpointer（短期记忆） | Store（长期记忆） |
|---|---|---|
| 范围 | 单个 thread 内的对话历史 | 跨所有 thread 的用户偏好/知识 |
| 生命周期 | 跟随 thread_id | 永久存储 |
| 类比 | "你5分钟前说了什么" | "你是一个喜欢 Python 的后端开发者" |
| API | `graph.compile(checkpointer=...)` | `graph.compile(store=...)` |

**实现 `services/memory.py`**：

```python
"""
Long-term Memory 服务
使用 LangGraph 的 Store API 实现跨会话记忆

【核心概念】
- Store 是一个 key-value 存储，按 namespace 组织
- namespace 通常用 (user_id, "memories") 这样的元组
- 支持语义搜索：存入的内容可以被向量化，按语义相似度检索
- 与 Checkpointer 互补：Checkpointer 管短期对话，Store 管长期偏好
"""
from langgraph.store.memory import InMemoryStore
# 生产环境用：
# from langgraph.store.redis.aio import AsyncRedisStore


def create_memory_store():
    """
    创建 Memory Store

    开发环境用 InMemoryStore，生产环境切换为：

        async with AsyncRedisStore.from_conn_string(redis_url) as store:
            await store.setup()
            graph = builder.compile(store=store, checkpointer=checkpointer)
    """
    store = InMemoryStore()
    return store
```

**在节点中使用 Store（通过 Runtime 注入）**：

```python
"""
chat_worker.py — 使用 Runtime 注入 Store

【学习重点】Runtime API
- Runtime 是 LangGraph 2025 新增的上下文注入机制
- 节点函数签名加上 runtime: Runtime 参数，LangGraph 自动注入
- 通过 runtime.store 访问长期记忆
- 通过 runtime.context 访问自定义上下文（如 user_id）
"""
import uuid
from dataclasses import dataclass

from langchain_core.messages import SystemMessage, HumanMessage, AIMessage
from langgraph.runtime import Runtime

from app.config import get_llm
from app.graph.state import AgentState


# 定义上下文 Schema（用于 Runtime 注入）
@dataclass
class UserContext:
    user_id: str


CHAT_SYSTEM_PROMPT = """你是一个智能博客平台助手。

{user_memories}

【职责】
- 友好、专业地回答用户问题
- 记住用户提到的偏好和信息
- 如果用户说"记住..."，将信息存入长期记忆
"""


async def chat_worker_node_with_memory(
    state: AgentState,
    runtime: Runtime[UserContext],  # LangGraph 自动注入
) -> dict:
    """
    带长期记忆的聊天 Worker

    Runtime 参数由 LangGraph 自动注入，包含：
    - runtime.store：Store 实例，用于读写长期记忆
    - runtime.context：UserContext 实例，包含 user_id
    """
    task_input = state["task_descriptions"].get("chat", state["user_message"])
    user_id = runtime.context.user_id

    # ===== 1. 读取长期记忆 =====
    namespace = (user_id, "memories")
    memories = await runtime.store.asearch(
        namespace,
        query=task_input,  # 按语义相似度搜索相关记忆
        limit=5,
    )
    memory_text = "\n".join([f"- {m.value['text']}" for m in memories])
    memory_section = f"【用户历史偏好】\n{memory_text}" if memory_text else ""

    # ===== 2. 构建消息并调用 LLM =====
    llm = get_llm()
    messages = [
        SystemMessage(content=CHAT_SYSTEM_PROMPT.format(user_memories=memory_section))
    ]

    for msg in state["history_messages"][-10:]:
        role = msg.get("role", "user")
        content = msg.get("content", "")
        if role == "user":
            messages.append(HumanMessage(content=content))
        else:
            messages.append(AIMessage(content=content))

    messages.append(HumanMessage(content=task_input))
    response = await llm.ainvoke(messages)

    # ===== 3. 提取并存储新的记忆 =====
    # 简单策略：如果用户说"记住"，就存入
    if "记住" in task_input or "remember" in task_input.lower():
        await runtime.store.aput(
            namespace,
            str(uuid.uuid4()),
            {"text": task_input},
        )

    return {
        "worker_results": [{
            "worker_name": "chat",
            "result": response.content,
        }]
    }
```

## 阶段三：Human-in-the-loop 人工审批

### 3.1 interrupt() + Command API（2025 最新）

**你会学到**：LangGraph 最强大的交互能力——在任意节点暂停执行，等待人工输入后继续。

**场景**：Writing Worker 生成文章草稿后，暂停等用户确认再发布。

**改造 `writing_worker.py`**：

```python
"""
Writing Worker — 加入人工审批

【学习重点】
1. interrupt(payload)：暂停图执行，payload 会返回给调用方
2. Command(resume=value)：恢复执行，value 成为 interrupt() 的返回值
3. Checkpointer 是前提：interrupt 依赖 Checkpointer 保存暂停时的状态
4. 节点重启机制：resume 时节点从头执行，interrupt 之前的代码会重新运行
"""
from typing import Literal
from langgraph.types import interrupt, Command
from langchain_core.messages import SystemMessage, HumanMessage, ToolMessage

from app.config import get_llm
from app.graph.state import AgentState
from app.tools.web_search import web_search
from app.tools.article_tool import search_articles, search_articles_by_knn


tool_map = {
    "web_search": web_search,
    "search_articles": search_articles,
    "search_articles_by_knn": search_articles_by_knn,
}
available_tools = [web_search, search_articles, search_articles_by_knn]

WRITING_SYSTEM_PROMPT = """你是一个专业的技术写作助手。根据任务要求撰写文章。"""


async def writing_worker_with_approval(state: AgentState) -> dict:
    """
    带人工审批的写作 Worker

    流程：
    1. LLM 生成草稿
    2. interrupt() 暂停，把草稿发给用户审批
    3. 用户 approve → 使用草稿
    4. 用户 reject + 修改意见 → 根据意见重写
    """
    task_input = state["task_descriptions"].get("writing", state["user_message"])
    llm = get_llm()
    llm_with_tools = llm.bind_tools(available_tools)

    # Step 1: 生成草稿
    messages = [
        SystemMessage(content=WRITING_SYSTEM_PROMPT),
        HumanMessage(content=f"写作任务：{task_input}"),
    ]

    # 工具调用循环（收集资料）
    for _ in range(2):
        response = await llm_with_tools.ainvoke(messages)
        if not response.tool_calls:
            break
        messages.append(response)
        for tc in response.tool_calls:
            fn = tool_map.get(tc["name"])
            result = await fn.ainvoke(tc["args"]) if fn else "工具不存在"
            messages.append(ToolMessage(content=result, tool_call_id=tc["id"]))
    else:
        response = await llm.ainvoke(messages)

    draft = response.content

    # ============== Step 2: 暂停等待审批 ==============
    #
    # interrupt() 做了两件事：
    # 1. 暂停图执行，保存当前 state 到 Checkpointer
    # 2. 把 payload 返回给调用方（前端可以展示给用户）
    #
    # 当用户调用 Command(resume=...) 时：
    # 1. resume 的值成为 interrupt() 的返回值
    # 2. 节点从头重新执行（！重要！interrupt 之前的代码会重新运行）
    #
    user_decision = interrupt({
        "type": "writing_approval",
        "draft": draft,
        "message": "请审阅这篇文章草稿，确认是否满意？",
    })

    # Step 3: 处理用户决策
    if isinstance(user_decision, dict):
        if user_decision.get("action") == "approve":
            final_content = draft
        elif user_decision.get("action") == "reject":
            # 用户给了修改意见，重新生成
            feedback = user_decision.get("feedback", "请改进")
            messages.append(HumanMessage(
                content=f"用户反馈：{feedback}。请根据反馈修改文章。"
            ))
            revised = await llm.ainvoke(messages)
            final_content = revised.content
        else:
            final_content = draft
    else:
        # 简单布尔值
        final_content = draft if user_decision else "用户取消了写作任务"

    return {
        "worker_results": [{
            "worker_name": "writing",
            "result": final_content,
        }]
    }
```

**前端/API 调用方式**：

```python
# Step 1: 发起写作请求（会在 interrupt 处暂停）
result = await graph.ainvoke(initial_state, config=config)
# result 中包含 interrupt 的 payload：
# {"type": "writing_approval", "draft": "...", "message": "请审阅..."}

# Step 2: 用户审阅后，发送审批结果恢复执行
from langgraph.types import Command

# 批准
result = await graph.ainvoke(
    Command(resume={"action": "approve"}),
    config=config,
)

# 或者拒绝 + 修改意见
result = await graph.ainvoke(
    Command(resume={"action": "reject", "feedback": "请加入更多代码示例"}),
    config=config,
)
```

**新增审批 API 到 `main.py`**：

```python
from langgraph.types import Command

class ApprovalRequest(BaseModel):
    conversation_id: int
    action: str  # "approve" or "reject"
    feedback: str = ""


@app.post("/chat/approve")
async def approve_writing(request: ApprovalRequest):
    """
    审批写作草稿

    当 writing_worker 使用 interrupt() 暂停后，
    前端调用这个接口恢复执行。
    """
    config = {
        "configurable": {
            "thread_id": f"conversation_{request.conversation_id}"
        }
    }

    # Command(resume=...) 恢复暂停的图执行
    result = await compiled_graph.ainvoke(
        Command(resume={
            "action": request.action,
            "feedback": request.feedback,
        }),

        reply=result["final_reply"],
        conversation_id=request.conversation_id,

```

> **学习要点**：
> - `interrupt(payload)` 暂停执行，`payload` 返回给调用方
> - `Command(resume=value)` 恢复执行，`value` 成为 `interrupt()` 的返回值
> - **Checkpointer 是前提**——没有 Checkpointer，interrupt 无法保存状态
> - **节点重启机制**：resume 时整个节点从头执行，interrupt 之前的代码会重新运行
>   - 所以 interrupt 之前的副作用必须是**幂等**的
>   - 或者把副作用放在 interrupt 之后
> - 不要把 `interrupt()` 放在 `try/except Exception` 里——它通过抛异常实现暂停

## 阶段四：子图拆分 + 流式输出 v2

### 4.1 把 search_worker 拆成子图（Subgraph）

**你会学到**：当一个节点逻辑变复杂时，如何拆成独立的 LangGraph 子图。

**现状问题**：`search_worker_node` 一个函数里塞了 query_rewrite → 粗检索 → rerank → LLM + tools 四个步骤，不好调试。

**拆分为子图**：

```python
"""
app/graph/nodes/search_subgraph.py

把 search_worker 拆成独立子图：
query_rewrite → coarse_retrieval → reranker → llm_generate

【学习重点】
1. 子图是一个独立的 StateGraph，有自己的 State
2. 子图可以直接作为父图的一个节点
3. 如果子图 State 和父图 State 有共享字段，数据自动流转
4. 如果 State 不同，需要在外层函数中做转换
"""
from typing import TypedDict, Annotated
from operator import add

from langgraph.graph import StateGraph, START, END
from langchain_core.messages import SystemMessage, HumanMessage, ToolMessage

from app.config import get_llm
from app.services.query_rewrite import QueryRewriteService
from app.services.reranker import RerankerService
from app.clients.es_client import EsVectorStore, EsComponent
from app.tools.web_search import web_search, do_search
from app.tools.article_tool import search_articles, search_articles_by_knn
from app.config import settings


# ===== 子图自己的 State =====
class SearchState(TypedDict):
    """搜索子图的内部状态"""
    query: str                    # 原始查询
    history_messages: list[dict]  # 对话历史
    rewrite_result: dict          # 改写后的查询
    candidates: list[dict]        # 粗检索结果
    ranked_docs: list[dict]       # 精排后的结果
    rag_context: str              # RAG 上下文
    final_answer: str             # 最终答案


# ===== 各节点 =====
query_rewrite_service = QueryRewriteService()
reranker_service = RerankerService()
es_vector_store = EsVectorStore()
es_component = EsComponent()


async def query_rewrite_node(state: SearchState) -> dict:
    """Step 1: 查询改写"""
    result = await query_rewrite_service.rewrite(
        state["query"], state["history_messages"]
    )
    return {"rewrite_result": result}


async def coarse_retrieval_node(state: SearchState) -> dict:
    """Step 2: 粗检索（多路召回）"""
    rewrite_result = state["rewrite_result"]
    doc_map = {}

    # 语义搜索
    for sq in rewrite_result.get("semantic_queries", []):
        try:
            chunks = await es_vector_store.search(
                sq, settings.COARSE_TOP_K, settings.COARSE_SIMILARITY_THRESHOLD
            )
            for chunk in chunks:
                key = f"{chunk['article_id']}_{chunk['chunk_index']}"
                if key not in doc_map:
                    doc_map[key] = chunk
        except Exception:
            pass

    # 关键词搜索
    for kw in rewrite_result.get("keywords", []):
        try:
            articles = await es_component.search(kw, page_size=5)
            for a in articles:
                key = f"keyword_{a['article_id']}"
                if key not in doc_map:
                    doc_map[key] = {
                        "article_id": a["article_id"],
                        "title": a["title"],
                        "content": a.get("summary", ""),
                        "chunk_index": 0,
                    }
        except Exception:
            pass

    # 兜底联网搜索
    if not doc_map:
        queries = rewrite_result.get("semantic_queries", []) or rewrite_result.get("keywords", [])
        if queries:
            try:
                web_results = await do_search(queries[0], size=5)
                for i, item in enumerate(web_results):
                    doc_map[f"web_{i}"] = {
                        "article_id": f"web_{i}",
                        "title": item.get("title", ""),
                        "content": item.get("content", ""),
                        "chunk_index": i,
                        "score": 0.1,
                    }
            except Exception:
                pass

    return {"candidates": list(doc_map.values())}


async def reranker_node(state: SearchState) -> dict:
    """Step 3: Reranker 精排"""
    candidates = state["candidates"]
    if candidates:
        ranked = reranker_service.rerank(state["query"], candidates)
    else:
        ranked = []

    # 构建 RAG 上下文
    if not ranked:
        rag_context = "未找到相关资料"
    else:
        parts = []
        for i, doc in enumerate(ranked[:5]):
            title = doc.get("title", "无标题")
            content = doc.get("content", "")[:500]
            parts.append(f"【{i+1}. {title}】\n{content}")
        rag_context = "\n\n".join(parts)

    return {"ranked_docs": ranked, "rag_context": rag_context}


async def llm_generate_node(state: SearchState) -> dict:
    """Step 4: LLM 生成 + 可选工具调用"""
    from datetime import datetime

    tool_map = {
        "web_search": web_search,
        "search_articles": search_articles,
        "search_articles_by_knn": search_articles_by_knn,
    }

    llm = get_llm()
    llm_with_tools = llm.bind_tools([web_search, search_articles, search_articles_by_knn])

    messages = [
        SystemMessage(content=f"你是信息检索助手。已通过 RAG 检索到参考资料。\n当前日期：{datetime.now().strftime('%Y-%m-%d')}"),
        HumanMessage(content=f"任务：{state['query']}\n\nRAG 参考资料：\n{state['rag_context']}"),
    ]

    response = await llm_with_tools.ainvoke(messages)

    if response.tool_calls:
        messages.append(response)
        for tc in response.tool_calls:
            fn = tool_map.get(tc["name"])
            result = await fn.ainvoke(tc["args"]) if fn else "工具不存在"
            messages.append(ToolMessage(content=result, tool_call_id=tc["id"]))
        response = await llm_with_tools.ainvoke(messages)

    return {"final_answer": response.content}


# ===== 构建子图 =====
def create_search_subgraph():
    """
    构建搜索子图

    流程：query_rewrite → coarse_retrieval → reranker → llm_generate
    """
    graph = StateGraph(SearchState)

    graph.add_node("query_rewrite", query_rewrite_node)
    graph.add_node("coarse_retrieval", coarse_retrieval_node)
    graph.add_node("reranker", reranker_node)
    graph.add_node("llm_generate", llm_generate_node)

    graph.add_edge(START, "query_rewrite")
    graph.add_edge("query_rewrite", "coarse_retrieval")
    graph.add_edge("coarse_retrieval", "reranker")
    graph.add_edge("reranker", "llm_generate")
    graph.add_edge("llm_generate", END)

    return graph.compile()


# ===== 在父图中使用 =====
search_subgraph = create_search_subgraph()


async def search_worker_node(state) -> dict:
    """
    包装器：把父图 State 转换为子图 State，调用子图，再转换回来。

    因为 SearchState 和 AgentState 的字段不同，
    所以需要手动转换。
    """
    task_input = state["task_descriptions"].get("search", state["user_message"])

    subgraph_result = await search_subgraph.ainvoke({
        "query": task_input,
        "history_messages": state["history_messages"],
        "rewrite_result": {},
        "candidates": [],
        "ranked_docs": [],
        "rag_context": "",
        "final_answer": "",
    })

    return {
        "worker_results": [{
            "worker_name": "search",
            "result": subgraph_result["final_answer"],
        }]
    }
```

> **学习要点**：
> - 子图有自己独立的 `State`，与父图隔离
> - 如果共享字段名，可以直接 `graph.add_node("name", compiled_subgraph)` 自动透传
> - 如果字段名不同，需要在外层函数中手动转换
> - 子图的每一步都可以单独调试：`search_subgraph.invoke({...})`
> - 父图的 Checkpointer 会自动传播到子图（不需要子图单独配置）

### 4.2 流式输出 v2 升级（2025 最新 stream API）

**你会学到**：LangGraph v2 统一流式格式，支持多种 stream mode 组合。

**v1 vs v2 的区别**：

| | v1（你现在用的） | v2（最新推荐） |
|---|---|---|
| 输出格式 | 根据参数不同格式不同 | 统一 `StreamPart` dict |
| 过滤方式 | `event["event"] == "on_chat_model_stream"` | `chunk["type"] == "messages"` |
| 多模式 | 返回 `(mode, data)` 元组 | `chunk["type"]` 区分模式 |
| 子图 | `(namespace, data)` 元组 | `chunk["ns"]` 字段 |

**升级后的流式接口**：

```python
# main.py — 使用 v2 stream API

@app.post("/chat/stream/v2")
async def chat_stream_v2(request: ChatRequest):
    """
    使用 LangGraph v2 流式 API

    支持多种 stream mode 同时使用：
    - "messages"：LLM token 级别的流式输出
    - "updates"：节点级别的状态更新
    - "custom"：自定义数据（如进度通知）
    """
    conversation_id = request.conversation_id or request.user_id
    initial_state = {
        "user_message": request.message,
        "history_messages": [],
        "active_workers": [],
        "task_descriptions": {},
        "worker_results": [],
        "final_reply": "",
    }
    config = {"configurable": {"thread_id": f"conversation_{conversation_id}"}}

    async def generate():
        async for chunk in compiled_graph.astream(
            initial_state,
            config=config,
            stream_mode=["messages", "updates"],  # 同时订阅多种模式
            version="v2",                          # 使用 v2 格式
        ):
            # v2 的所有 chunk 都是统一格式的 dict
            if chunk["type"] == "messages":
                # LLM token 级别的流式输出
                msg, metadata = chunk["data"]
                # 只推送 synthesizer 节点的输出
                if msg.content and metadata.get("langgraph_node") == "synthesizer":
                    yield f"data: {json.dumps({'type': 'token', 'content': msg.content})}\n\n"

            elif chunk["type"] == "updates":
                # 节点级别的状态更新（可用于进度展示）
                for node_name in chunk["data"]:
                    if node_name != "__start__":
                        yield f"data: {json.dumps({'type': 'progress', 'node': node_name})}\n\n"

        yield "data: [DONE]\n\n"

    return StreamingResponse(generate(), media_type="text/event-stream")
```

**使用 `get_stream_writer` 发送自定义进度**：

```python
# 在任意节点中发送自定义流式数据
from langgraph.config import get_stream_writer

    writer = get_stream_writer()

    writer({"status": "正在检索文档...", "progress": 50})
    candidates = await execute_coarse_retrieval(rewrite_result)

    writer({"status": "正在精排结果...", "progress": 80})
    ranked = reranker_service.rerank(...)

    writer({"status": "正在生成回答...", "progress": 90})
    # ... LLM 生成 ...

    return {"worker_results": [...]}
```

> **学习要点**：
> - `version="v2"` 是 LangGraph >= 1.1 的新格式，所有输出统一为 `StreamPart` dict
> - `stream_mode` 支持传列表，同时订阅多种模式
> - `chunk["type"]` 区分模式：`"messages"` / `"updates"` / `"custom"` / `"checkpoints"` 等
> - `chunk["ns"]` 标识来源（空元组=根图，非空=子图）
> - `get_stream_writer()` 可在任意节点/工具中发送自定义实时数据

## 阶段五：Runtime 上下文注入 + Multi-Agent

### 5.1 Runtime API——类型安全的上下文注入

**你会学到**：2025 年新增的 `Runtime` API，取代老版的 `config["configurable"]` 传参方式。

```python
"""
使用 Runtime 注入上下文

老方式（不推荐）：
    config = {"configurable": {"user_id": "123"}}
    def my_node(state, config):
        user_id = config["configurable"]["user_id"]  # 无类型检查

新方式（推荐）：
    from langgraph.runtime import Runtime
    
    @dataclass
    class Context:
        user_id: str
    
    def my_node(state, runtime: Runtime[Context]):
        user_id = runtime.context.user_id  # 有类型检查、IDE 自动补全
"""
from dataclasses import dataclass
from langgraph.runtime import Runtime
from langgraph.graph import StateGraph, MessagesState


@dataclass
class AppContext:
    """应用上下文——在调用图时传入，所有节点都能访问"""
    user_id: str
    user_role: str = "normal"     # 用户角色（normal/vip/admin）
    platform: str = "web"         # 来源平台（web/app/api）


# 构建图时声明 context_schema
graph = StateGraph(AgentState, context_schema=AppContext)

# 调用时传入 context
result = await graph.ainvoke(
    initial_state,
    config={"configurable": {"thread_id": "xxx"}},
    context=AppContext(user_id="123", user_role="vip"),
)
```

### 5.2 Multi-Agent 架构——Worker 升级为独立 Agent

**你会学到**：把 Worker 从"函数节点"升级为"独立 Agent 子图"，每个 Agent 有自己的工具和决策循环。

```python
"""
Multi-Agent 架构示意

当前架构：Planner → 简单 Worker 函数
目标架构：Planner → 独立 Agent 子图（每个 Agent 有自己的工具循环）

这是 LangGraph 最高级的用法，适合复杂业务场景。
"""
from langchain.agents import create_agent
from langchain.tools import tool


# ===== 定义各领域的专家 Agent =====

@tool
def search_platform_articles(query: str) -> str:
    """搜索平台内的技术文章"""
    # ... 调用 ES ...
    return "搜索结果..."

@tool
def web_search_tool(query: str) -> str:
    """联网搜索"""
    # ... 调用博查 ...
    return "联网结果..."


# 搜索专家 Agent（有自己的工具和推理循环）
search_agent = create_agent(
    model="deepseek-chat",
    tools=[search_platform_articles, web_search_tool],
    system_prompt="你是信息检索专家，擅长搜索和整理信息。",
)

# 写作专家 Agent
writing_agent = create_agent(
    model="deepseek-chat",
    tools=[search_platform_articles],
    system_prompt="你是技术写作专家，擅长撰写高质量的技术文章。",
)

# 然后在父图中把这些 Agent 作为节点或工具使用
# 详见 LangChain 官方 Multi-Agent 文档
```

> **学习要点**：
> - `create_agent` 是 LangChain 2025 新增的高级 API，一行创建完整 Agent
> - 每个 Agent 是一个独立的 LangGraph 子图，有自己的工具循环和决策逻辑
> - 父图通过 Planner 调度各 Agent，形成 Multi-Agent 协作
> - 适合复杂业务场景，简单场景用普通 Worker 函数即可
