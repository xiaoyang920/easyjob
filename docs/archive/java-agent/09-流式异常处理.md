# AI Agent 流式聊天异常处理

## 问题背景

AI聊天使用SSE流式接口（`/api/agent/chat/stream`），返回 `Flux<String>`，不走 `GlobalExceptionHandler`。当智谱API返回429限流错误时，异常直接在Flux流里抛出，前端收到原始500错误，无法给用户友好提示。

## 解决方案

### 后端改造 - AgentService.java

在 `chatStream` 方法的 `Flux.concat(...)` 末尾添加 `.onErrorResume` 捕获异常：

```java
public Flux<String> chatStream(Long conversationId, Long userId, String userMessage, List<String> imagePaths){
    // ... 前面代码不变 ...
    
    return Flux.concat(
        // 先发送会话ID
        Flux.just("__CONV_ID__:" + finalConversionId),
        // AI流式回复
        chatClient.prompt()
                .messages(messages)
                .tools(articleTool, bochaSearchTool)
                .toolContext(Map.of("conversationId", finalConversionId))
                .stream()
                .content()
                .doOnNext(fullReply::append)
                .doOnComplete(() -> {
                    List<ArticleCardVO> articles = redisComponent.getAndClearArticleCards(finalConversionId);
                    articleCardsRef.set(articles);
                    aiConversationService.addMessage(finalConversionId, userId, "assistant", fullReply.toString(), null,
                            articles.isEmpty() ? null : articles);
                }),
        // 流结束后追加文章卡片数据
        Flux.defer(() -> {
            List<ArticleCardVO> articles = articleCardsRef.get();
            if (!articles.isEmpty()) {
                String json = JSON.toJSONString(articles);
                return Flux.just("__ARTICLES__:" + json);
            }
            return Flux.empty();
        })
    ).onErrorResume(e -> {
        log.error("流式聊天异常", e);
        String errorMsg;
        if (isRateLimitError(e)) {
            errorMsg = "[ERROR] 模型当前访问量过大，请稍后再试";
        } else {
            errorMsg = "[ERROR] AI服务暂时不可用，请稍后重试";
        }
        return Flux.just(errorMsg);
    });
}

/**
 * 判断异常是否为模型限流（HTTP 429）
 */
private boolean isRateLimitError(Throwable e) {
    Throwable cause = e;
    while (cause != null) {
        String message = cause.getMessage();
        if (message != null && (message.contains("429") || message.contains("访问量过大") || message.contains("rate limit"))) {
            return true;
        }
        cause = cause.getCause();
    }
    return false;
}
```

### 前端处理 - AiChat.vue

前端已有 `[ERROR]` 标识处理逻辑，无需修改：

```typescript
// streamChat 函数中
if (data.startsWith('[ERROR]')) {
  throw new Error(data.substring(7).trim())
}
```

catch 块会显示错误：
```typescript
ElMessage.error(error.message || '请求失败')
```

## 错误类型映射

| 后端异常 | 前端提示 |
|---------|---------|
| HTTP 429 / 访问量过大 | 模型当前访问量过大，请稍后再试 |
| 其他异常 | AI服务暂时不可用，请稍后重试 |

## 扩展

如需支持更多错误类型，在 `onErrorResume` 中添加判断逻辑即可，比如：
- 余额不足：`message.contains("insufficient_quota")`
- 内容审核：`message.contains("content_filter")`
