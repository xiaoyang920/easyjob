#### 1. 敏感信息外置

**问题**：API Key、数据库密码明文写在 `application.yml`，一旦代码泄露，密钥全部暴露。

**方案**：

```yaml
# application.yml - 使用环境变量
spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
    zhipuai:
      api-key: ${ZHIPUAI_API_KEY}
  datasource:
    password: ${DB_PASSWORD}

agent:
  bocha:
    api-key: ${BOCHA_API_KEY}
```

**部署时**：
```bash
# Linux/Mac
export DEEPSEEK_API_KEY=sk-xxx
export ZHIPUAI_API_KEY=xxx
export BOCHA_API_KEY=xxx
export DB_PASSWORD=xxx

# 或使用 .env 文件 + docker-compose
```

**进阶方案**：使用 Vault、AWS Secrets Manager、阿里云 KMS 等密钥管理服务。

#### 2. Agent 调用重试机制

**问题**：LLM 调用（DeepSeek/智谱）和 Tool 调用（博查搜索）失败时直接返回错误，无重试。

**方案**：添加 Spring Retry 依赖并配置重试策略。

```xml
<!-- pom.xml -->
<dependency>
    <groupId>org.springframework.retry</groupId>
    <artifactId>spring-retry</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>
```

```java
// 启用重试
@EnableRetry
@SpringBootApplication
public class EasyjobApplication { ... }

// AgentService 中使用
@Retryable(
    retryFor = {WebClientException.class, TimeoutException.class},
    maxAttempts = 3,
    backoff = @Backoff(delay = 1000, multiplier = 2)
)
public String callLLM(String prompt) {
    return chatClient.prompt().user(prompt).call().content();
}

@Recover
public String recoverLLM(Exception e, String prompt) {
    log.error("LLM调用重试3次后仍失败", e);
    return "抱歉，AI 服务暂时不可用，请稍后重试";
}
```

**Tool 调用重试**（BochaSearchTool）：

```java
@Retryable(maxAttempts = 2, backoff = @Backoff(delay = 500))
@Tool(description = "联网搜索工具...")
public String webSearch(String query, String freshness) {
    // 现有逻辑
}
```

#### 3. 接口限流保护

**问题**：AI 接口无限流，恶意用户可无限调用，导致 Token 成本爆炸。

**方案 A**：基于 Redis 的简单限流（推荐先用这个）

```java
@Component
public class RateLimiter {
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    /**
     * 检查是否超过限流
     * @param key 限流键（如 "agent:rate:userId:123"）
     * @param limit 时间窗口内最大请求数
     * @param windowSeconds 时间窗口（秒）
     */
    public boolean isAllowed(String key, int limit, int windowSeconds) {
        String countStr = redisTemplate.opsForValue().get(key);
        int count = countStr == null ? 0 : Integer.parseInt(countStr);
        
        if (count >= limit) {
            return false;
        }
        
        redisTemplate.opsForValue().increment(key);
        if (count == 0) {
            redisTemplate.expire(key, windowSeconds, TimeUnit.SECONDS);
        }
        return true;
    }
}
```

```java
// AgentController 中使用
@PostMapping("/chat/stream")
public Flux<String> chatStream(@RequestBody AiChatParam param) {
    Long userId = UserContext.getUserId();
    
    // 限流：每用户每分钟最多 10 次
    if (!rateLimiter.isAllowed("agent:rate:" + userId, 10, 60)) {
        return Flux.just("[ERROR] 请求过于频繁，请稍后再试");
    }
    
    // 原有逻辑...
}
```

**方案 B**：使用 Resilience4j（更强大，支持熔断）

```xml
<dependency>
    <groupId>io.github.resilience4j</groupId>
    <artifactId>resilience4j-spring-boot3</artifactId>
    <version>2.2.0</version>
</dependency>
```

```yaml
# application.yml
resilience4j:
  ratelimiter:
    instances:
      agentChat:
        limitForPeriod: 10          # 每周期允许的请求数
        limitRefreshPeriod: 60s     # 周期时长
        timeoutDuration: 0s         # 等待时间（0表示立即拒绝）
```

```java
@RateLimiter(name = "agentChat", fallbackMethod = "chatRateLimitFallback")
public Flux<String> chatStream(...) { ... }

public Flux<String> chatRateLimitFallback(AiChatParam param, RequestNotPermitted e) {
    return Flux.just("[ERROR] 请求过于频繁，请稍后再试");
}
```

#### 4. 超时控制

**问题**：LLM 调用可能因网络问题或模型负载高而长时间无响应，导致请求挂死。

**方案**：

```yaml

  ai:
    deepseek:
```

```java
    .readTimeout(30, TimeUnit.SECONDS)      // 读取超时
    .writeTimeout(10, TimeUnit.SECONDS)     // 写入超时
    .build();
```

### 🟢 P2 - 锦上添花（用户体验/高级功能）

#### 9. Agent 反思机制（Reflection）

**目标**：Worker 执行后评估结果质量，不满意时自动重试或换策略。

**方案**：在 Synthesizer 后添加 Evaluator 节点

```java
public class EvaluatorNode implements NodeAction {
    
    private static final String EVAL_PROMPT = """
        评估以下回复是否充分回答了用户问题。
        
        用户问题：%s
        AI回复：%s
        
        输出JSON：{"score": 1-5, "reason": "评分理由", "needRetry": true/false}
        """;
    
    @Override
    public Map<String, Object> apply(OverAllState state) {
        String userMessage = state.value("userMessage", "");
        String finalReply = state.value("finalReply", "");
        
        // 调用 LLM 评估
        String evalResult = chatClient.prompt()
            .user(EVAL_PROMPT.formatted(userMessage, finalReply))
            .call().content();
        
        JSONObject eval = JSON.parseObject(evalResult);
        if (eval.getBoolean("needRetry")) {
            // 标记需要重试，Graph 条件边跳回 Planner
            return Map.of("needRetry", true, "retryReason", eval.getString("reason"));
        }
        
        return Map.of("needRetry", false);
    }
}
```

**Graph 拓扑调整**：

```
START → Planner → Dispatcher → Synthesizer → Evaluator → (条件边)
                                                ↓
                                         needRetry=true → Planner（最多重试1次）
                                         needRetry=false → END
```

#### 11. Human-in-the-loop

**目标**：敏感操作（如删除文章、发布内容）让用户确认后再执行。

**方案**：

```java
// 定义需要确认的操作
public enum ConfirmableAction {
    DELETE_ARTICLE,
    PUBLISH_ARTICLE,
    SEND_EMAIL
}

// Worker 返回确认请求而非直接执行
public class WritingWorkerNode implements NodeAction {
    @Override
    public Map<String, Object> apply(OverAllState state) {
        String task = state.value("taskDescriptions.writing", "");
        
        if (task.contains("发布") || task.contains("删除")) {
            return Map.of(
                "workerResults", Map.of(
                    "workerName", "writing",
                    "result", "__CONFIRM_REQUIRED__",
                    "action", "PUBLISH_ARTICLE",
                    "preview", "即将发布文章《xxx》，确认吗？"
                )
            );
        }
        
        // 正常执行
    }
}
```

**前端处理**：收到 `__CONFIRM_REQUIRED__` 时弹出确认框，用户确认后发送 `/api/agent/confirm` 接口。

#### 12. 成本控制（Token 配额）

**目标**：限制每用户每日/每月 Token 消耗，防止成本失控。

**方案**：

```sql
-- 用户配额表
CREATE TABLE user_token_quota (
    user_id BIGINT PRIMARY KEY,
    daily_limit INT DEFAULT 100000,      -- 每日 Token 上限
    monthly_limit INT DEFAULT 2000000,   -- 每月 Token 上限
    daily_used INT DEFAULT 0,
    monthly_used INT DEFAULT 0,
    last_daily_reset DATE,
    last_monthly_reset DATE
);
```

```java
@Service
public class TokenQuotaService {
    
    public boolean checkAndConsume(Long userId, int tokens) {
        UserTokenQuota quota = quotaMapper.selectById(userId);
        
        // 重置逻辑（每日/每月）
        resetIfNeeded(quota);
        
        if (quota.getDailyUsed() + tokens > quota.getDailyLimit()) {
            return false;  // 超出每日配额
        }
        
        // 扣减配额
        quotaMapper.incrementUsed(userId, tokens);
        return true;
    }
}
```
