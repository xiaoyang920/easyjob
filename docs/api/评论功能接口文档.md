# 文章评论功能接口文档

## 一、数据库表设计

### comment 评论表（两层评论结构）

```sql
CREATE TABLE comment (
    -- 主键
    comment_id BIGINT PRIMARY KEY COMMENT '评论ID（雪花算法）',
    
    -- 评论关联信息
    article_id BIGINT NOT NULL COMMENT '文章ID',
    article_user_id BIGINT NOT NULL COMMENT '文章作者ID',
    parent_id BIGINT NOT NULL DEFAULT 0 COMMENT '父评论ID：0表示顶级评论，非0表示回复（指向顶级评论）',
    
    -- 评论内容
    content VARCHAR(500) NOT NULL COMMENT '评论内容',
    img_path VARCHAR(150) DEFAULT NULL COMMENT '评论配图URL',
    
    -- 评论者信息（冗余）
    user_id BIGINT NOT NULL COMMENT '评论者ID',
    user_nick_name VARCHAR(50) NOT NULL COMMENT '评论者昵称（冗余）',
    user_avatar VARCHAR(200) DEFAULT NULL COMMENT '评论者头像（冗余）',
    
    -- 被回复者信息（冗余）- 用于显示 "@某人"
    reply_user_id BIGINT DEFAULT NULL COMMENT '被回复用户ID（回复二级评论时有值）',
    reply_nick_name VARCHAR(50) DEFAULT NULL COMMENT '被回复用户昵称（冗余）',
    reply_avatar VARCHAR(200) DEFAULT NULL COMMENT '被回复用户头像（冗余）',
    
    -- 状态与统计
    top_type TINYINT NOT NULL DEFAULT 0 COMMENT '是否置顶：0否 1是',
    status TINYINT NOT NULL DEFAULT 0 COMMENT '状态：0正常 1已删除 2审核中 3已折叠',
    like_count INT NOT NULL DEFAULT 0 COMMENT '点赞数',
    reply_count INT NOT NULL DEFAULT 0 COMMENT '回复数（仅顶级评论有效）',
    
    -- 时间字段
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    
    -- 索引
    INDEX idx_article_id_create_time (article_id, create_time DESC) COMMENT '查询文章评论列表（按时间倒序）',
    INDEX idx_article_id_like_count (article_id, like_count DESC) COMMENT '查询文章评论列表（按热度倒序）',
    INDEX idx_parent_id (parent_id) COMMENT '查询某条评论的所有回复',
    INDEX idx_user_id (user_id) COMMENT '查询用户的所有评论',
    INDEX idx_article_user_id (article_user_id) COMMENT '查询收到的评论（文章作者视角）',
    INDEX idx_status (status) COMMENT '管理后台审核、删除操作'
    
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文章评论表';
```

### 3. 上传评论图片

**接口**: `POST /api/file/upload-comment-image`

**描述**: 上传评论配图（在发布评论前先调用）

**请求头**:
```
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

**请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|---------|
| file | File | 是 | 图片文件（支持jpg/jpeg/png/gif/webp，最大5MB） |

**响应数据**:

```json
{
    "code": 200,
    "message": "上传成功",
    "data": {
        "url": "/uploads/comments/2026/01/29/abc123.jpg",
        "fileName": "screenshot.png"
    }
}
```

**错误响应**:

```json
{
    "code": 400,
    "message": "文件大小不能超过15MB"
}
```

**使用流程**:

1. 用户选择图片 → 前端立即调用此接口上传
2. 后端返回图片URL
3. 前端保存URL，发布评论时传给 `/comment/create` 接口

### 4. 发布评论

**接口**: `POST /api/comment/create`

**描述**: 发布评论或回复评论

**请求头**:
```
Authorization: Bearer <token>
Content-Type: application/json
```

**请求参数**:

```json
{
    "articleId": "9876543210987654321",
    "articleUserId": "1234567890123456789",
    "content": "这是评论内容",
    "imgPath": "/uploads/comments/2026/01/29/abc123.jpg",
    "parentId": 0,
    "replyUserId": null
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| articleId | Long | 是 | 文章ID |
| articleUserId | Long | 是 | 文章作者ID（用于消息通知） |
| content | String | 是 | 评论内容（1-500字符） |
| imgPath | String | 否 | 评论配图URL（通过上传接口获得） |
| parentId | Long | 否 | 父评论id，0或不传表示顶级评论 |
| replyUserId | Long | 否 | 被回复用户ID（回复评论时传） |

**响应数据**:

```json
{
    "code": 200,
    "message": "评论成功",
    "data": {
        "commentId": "3456789012345678901",
        "articleId": "9876543210987654321",
        "parentId": "0",
        "rootId": "3456789012345678901",
        "content": "这是评论内容",
        "userId": "111222333444555666",
        "userNickName": "张三",
        "userAvatar": "/uploads/avatars/xxx.jpg",
        "likeCount": 0,
        "replyCount": 0,
        "createTime": "2024-01-20T12:00:00"
    }
}
```

**业务逻辑**:

1. **发布顶级评论**：`parentId = 0` 或不传
   - 创建评论后，`root_id` 设为自己的 `comment_id`
   
2. **回复评论（两层扁平化）**：
   - 如果 `parentId` 对应的是顶级评论，`root_id = parentId`
   - 如果 `parentId` 对应的是回复评论，继承其 `root_id`（自动扁平化）
   - 冗余被回复者信息（`reply_user_id`, `reply_nick_name`, `reply_avatar`）
   - 更新根评论的 `reply_count + 1`

### 4. 删除评论

**接口**: `DELETE /api/comment/{commentId}`

**描述**: 删除自己的评论（软删除）

**请求头**:
```
Authorization: Bearer <token>
```

**路径参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| commentId | Long | 是 | 评论ID |

**响应数据**:

```json
{
    "code": 200,
    "message": "删除成功"
}
```

**业务逻辑**:

1. 只能删除自己的评论
2. 如果是顶级评论，同时软删除所有回复
3. 如果是回复评论，更新根评论的 `reply_count - 1`

**错误码**:

| 错误码 | 说明 |
|--------|------|
| 400 | 评论不存在 |
| 403 | 只能删除自己的评论 |

### 5. 点赞/取消点赞评论

**接口**: `POST /api/comment/{commentId}/action`

**描述**: 点赞评论，再次调用取消点赞（Toggle）

**请求头**:
```
Authorization: Bearer <token>
```

**路径参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| commentId | Long | 是 | 评论ID |

**响应数据**:

```json
{
    "code": 200,
    "message": "点赞成功",
    "data": {
        "hasLiked": true,
        "likeCount": 67
    }
}
```

**业务逻辑**:

1. 检查用户是否已点赞该评论
2. 已点赞 → 取消点赞，`like_count - 1`
3. 未点赞 → 点赞，`like_count + 1`
4. 记录到 `comment_like` 表（可选）

## 四、后端实现要点

### 1. 发布评论逻辑

```java
@PostMapping("/create")
@Transactional
public ResponseVO<?> createComment(@RequestBody CommentCreateDTO dto) {
    Long userId = UserContext.getUserId();
    UserSpaceVO userInfo = redisComponent.getUserSpaceVO(userId);
    
    Comment comment = new Comment();
    comment.setArticleId(dto.getArticleId());
    comment.setContent(dto.getContent());
    comment.setUserId(userId);
    comment.setUserNickName(userInfo.getNickName());
    comment.setUserAvatar(userInfo.getAvatar());
    
    Long parentId = dto.getParentId() != null ? dto.getParentId() : 0L;
    comment.setParentId(parentId);
    
    if (parentId == 0) {
        // 顶级评论
        comment.setRootId(0L);  // 先设为0，插入后更新
    } else {
        // 回复评论 - 自动扁平化
        Comment parentComment = commentMapper.selectById(parentId);
        Long rootId = parentComment.getParentId() == 0 
                      ? parentComment.getCommentId() 
                      : parentComment.getRootId();
        
        comment.setParentId(rootId);  // 挂到根评论下
        comment.setRootId(rootId);
        
        // 冗余被回复者信息
        if (dto.getReplyUserId() != null) {
            UserSpaceVO replyUser = redisComponent.getUserSpaceVO(dto.getReplyUserId());
            comment.setReplyUserId(dto.getReplyUserId());
            comment.setReplyNickName(replyUser.getNickName());
            comment.setReplyAvatar(replyUser.getAvatar());
        }
    }
    
    // 设置文章作者ID
    Article article = articleMapper.selectById(dto.getArticleId());
    comment.setArticleUserId(Long.valueOf(article.getUserId()));
    
    commentMapper.insert(comment);
    
    // 如果是顶级评论，更新 root_id
    if (parentId == 0) {
        comment.setRootId(comment.getCommentId());
        commentMapper.updateById(comment);
    } else {
        // 更新根评论的回复数
        commentMapper.update(null, 
            new LambdaUpdateWrapper<Comment>()
                .setSql("reply_count = reply_count + 1")
                .eq(Comment::getCommentId, comment.getRootId())
        );
    }
    
    return ResponseVO.success("评论成功", comment);
}
```

    @RequestParam Long articleId,

    @RequestParam(defaultValue = "10") Integer size,
    @RequestParam(defaultValue = "hot") String sort
) {
    Page<Comment> commentPage = new Page<>(page, size);
    
    LambdaQueryWrapper<Comment> wrapper = new LambdaQueryWrapper<Comment>()
        .eq(Comment::getArticleId, articleId)
        .eq(Comment::getParentId, 0)  // 只查顶级评论
