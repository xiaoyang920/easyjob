# 点赞、收藏、投币功能接口文档

## 1. 概述

本文档描述了文章的点赞、收藏、投币等用户行为相关的API接口。所有接口需要用户登录后携带JWT token访问。

## 2. 数据表结构

### 2.1 user_action 表

| 字段名 | 类型 | 说明 |
|--------|------|------|
| action_id | bigint | 自增ID（主键） |
| article_id | varchar(10) | 文章ID（字符串类型） |
| article_user_id | varchar(10) | 文章作者用户ID（字符串类型） |
| comment_id | int | 评论ID（针对评论的操作） |
| action_type | tinyint | 操作类型：0=评论点赞，1=讨厌评论，2=文章点赞，3=文章收藏，4=文章投币 |
| action_count | int | 数量（投币数量等） |
| user_id | varchar(10) | 操作用户ID（字符串类型） |
| action_time | datetime | 操作时间 |

**重要说明**：
- `article_id`、`article_user_id`、`user_id` 在数据库中为 `varchar(10)` 类型
- 后端实体类中对应 `String` 类型，避免 JavaScript 精度丢失问题
- 接口传参时统一使用字符串类型

### 2.2 索引说明

- **唯一索引**: `idx_key_video_comment_type_user` (article_id, comment_id, action_type, user_id) - 防止重复操作
- **普通索引**: article_id, user_id, action_type, action_time - 加速查询

## 3. 操作类型枚举

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | COMMENT_LIKE | 评论点赞 |
| 1 | COMMENT_DISLIKE | 讨厌评论 |
| 2 | ARTICLE_LIKE | 文章点赞 |
| 3 | ARTICLE_COLLECT | 文章收藏 |
| 4 | ARTICLE_COIN | 文章投币 |

## 4. API接口

### 4.1 文章点赞

#### 4.1.1 点赞/取消点赞文章

**接口地址**: `POST /api/action/article/{articleId}/like`

**接口描述**: 对文章进行点赞或取消点赞操作

**请求头**:
```http
Authorization: Bearer <token>
Content-Type: application/json
```

**路径参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| articleId | String | 是 | 文章ID |

**请求体**:
```json
{
  "action": true
}
```

**请求参数说明**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| action | Boolean | 是 | true=点赞，false=取消点赞 |

**响应成功** (点赞):
```json
{
  "status": "success",
  "code": 200,
  "message": "操作成功",
  "data": {
    "success": true,
    "status": true,
    "actionTypeName": "文章点赞",
    "count": 101,
    "message": "点赞成功"
  }
}
```

**响应成功** (取消点赞):
```json
{
  "status": "success",
  "code": 200,
  "message": "操作成功",
  "data": {
    "success": true,
    "status": false,
    "actionTypeName": "文章点赞",
    "count": 100,
    "message": "已取消点赞"
  }
}
```

**响应失败**:
```json
{
  "status": "error",
  "code": 400,
  "message": "操作失败，请稍后重试"
}
```

**业务逻辑**:
1. 检查用户是否已点赞（查询 user_action 表）
2. 如果 action=true 且未点赞，插入点赞记录
3. 如果 action=false 且已点赞，删除点赞记录
4. 更新文章的 like_count 字段
5. 返回最新的点赞数

**SQL 示例**:
```sql
-- 检查是否已点赞
SELECT * FROM user_action 
WHERE article_id = ? 
  AND user_id = ? 
  AND action_type = 2 
  AND comment_id = 0;

-- 插入点赞记录
INSERT INTO user_action (article_id, article_user_id, comment_id, action_type, action_count, user_id, action_time)
VALUES (?, ?, 0, 2, 1, ?, NOW());

-- 删除点赞记录
DELETE FROM user_action 
WHERE article_id = ? 
  AND user_id = ? 
  AND action_type = 2 
  AND comment_id = 0;

-- 更新文章点赞数
UPDATE article_info 
SET like_count = like_count + 1 
WHERE article_id = ?;
```

### 4.3 文章投币

#### 4.3.1 给文章投币

**接口地址**: `POST /api/action/article/{articleId}/coin`

**接口描述**: 给文章投硬币（支持投1个或2个硬币）

**请求头**:
```http
Authorization: Bearer <token>
Content-Type: application/json
```

**路径参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| articleId | String | 是 | 文章ID |

**请求体**:
```json
{
  "coinCount": 1,
  "action": true
}
```

**请求参数说明**:

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| coinCount | Integer | 否 | 1 | 投币数量，可选值：1或2 |
| action | Boolean | 是 | - | true=投币，false=取消投币 |

**响应成功** (投币):
```json
{
  "status": "success",
  "code": 200,
  "message": "操作成功",
  "data": {
    "success": true,
    "status": true,
    "actionTypeName": "文章投币",
    "count": 2,
    "message": "投币成功，消耗 2 个硬币"
  }
}
```

**响应失败** (硬币不足):
```json
{
  "status": "error",
  "code": 400,
  "message": "硬币余额不足"
}
```

**业务逻辑**:
1. 检查用户硬币余额是否充足
2. 检查是否已经投过币（每篇文章只能投一次）
3. 扣除用户硬币
4. 插入投币记录
5. 增加文章作者的硬币
6. 更新文章的 coin_count 字段
7. 返回操作结果

**注意事项**:
- 每篇文章只能投币一次
- 投币后不可取消
- 投币数量只能是1或2

```sql
  AND comment_id = 0
```

## 5. 前端集成示例

### 5.1 文章点赞

```javascript
// 点赞文章
async function likeArticle(articleId) {
    const token = localStorage.getItem('token');
    
    const response = await fetch(`/api/action/article/${articleId}/like`, {
        method: 'POST',
        headers: {
            'Authorization': `Bearer ${token}`,
            'Content-Type': 'application/json'
        },
        body: JSON.stringify({ action: true })
    });
    
    const result = await response.json();
    
    if (result.status === 'success') {
        console.log('点赞成功，当前点赞数:', result.data.count);
        // 更新UI
        updateLikeButton(true, result.data.count);
    } else {
        alert(result.message);
    }
}

// 取消点赞
async function unlikeArticle(articleId) {
    const token = localStorage.getItem('token');
    
    const response = await fetch(`/api/action/article/${articleId}/like`, {
        method: 'POST',
        headers: {
            'Authorization': `Bearer ${token}`,
            'Content-Type': 'application/json'
        },
        body: JSON.stringify({ action: false })
    });
    
    const result = await response.json();
    
    if (result.status === 'success') {
        console.log('取消点赞成功，当前点赞数:', result.data.count);
        // 更新UI
        updateLikeButton(false, result.data.count);
    }
}
```

### 5.2 获取用户行为状态

```javascript
// 加载文章时获取用户的操作状态
async function loadArticleActionStatus(articleId) {

    const response = await fetch(`/api/action/article/${articleId}/status`, {
        method: 'GET',
        headers: {
            'Authorization': `Bearer ${token}`,

    const result = await response.json();
    
    if (result.status === 'success') {
        const data = result.data;
        
        // 更新按钮状态

            document.getElementById('likeBtn').classList.add('active');
        }
        if (data.hasCollected) {
            document.getElementById('collectBtn').classList.add('active');
        }
        if (data.hasCoin) {
            document.getElementById('coinBtn').classList.add('active');
            document.getElementById('coinBtn').textContent = `已投币 ${data.coinCount}`;
        }
    }
}
```

## 6. 错误码说明

| 错误码 | 说明 |
|--------|------|
| 200 | 操作成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或token已失效 |
| 403 | 无权限操作 |
| 404 | 文章或评论不存在 |
| 409 | 重复操作（已点赞/已收藏/已投币） |
| 500 | 服务器内部错误 |

## 7. 注意事项

1. **幂等性**: 点赞、收藏操作支持幂等性，重复调用不会产生副作用
2. **投币限制**: 每篇文章只能投币一次，投币后不可撤销
3. **数据一致性**: 使用数据库唯一索引保证不会出现重复操作记录
4. **性能优化**: 建议前端缓存用户的操作状态，避免频繁请求
5. **安全性**: 所有操作都需要验证用户身份，防止刷量行为
6. **事务处理**: 投币操作涉及扣币、加币、更新统计等多个步骤，需使用数据库事务保证一致性

## 8. 数据库优化建议

### 8.1 推荐索引

```sql
-- 联合唯一索引（已存在）
CREATE UNIQUE INDEX idx_key_video_comment_type_user 
ON user_action(article_id, comment_id, action_type, user_id);

-- 查询用户行为历史
CREATE INDEX idx_user_time 
ON user_action(user_id, action_time);

-- 查询文章被操作记录
CREATE INDEX idx_article_type_time 
ON user_action(article_id, action_type, action_time);
```

### 8.2 统计数据维护

建议在 article_info 表维护以下统计字段：
- `like_count`: 点赞数
- `collect_count`: 收藏数
- `coin_count`: 投币数

每次操作后及时更新这些字段，避免实时统计带来的性能问题。
