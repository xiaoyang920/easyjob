# 粉丝与关注功能接口文档

## 数据表结构

```sql
CREATE TABLE user_focus (
    user_id VARCHAR(10) NOT NULL COMMENT '用户ID',
    focus_user_id VARCHAR(10) NOT NULL COMMENT '关注的用户ID',
    focus_time DATETIME COMMENT '关注时间',
    PRIMARY KEY (user_id, focus_user_id),
    INDEX idx_user_id (user_id),
    INDEX idx_focus_user_id (focus_user_id),
    INDEX idx_focus_time (focus_time)
) COMMENT='用户关注表';
```

---

## 1. 获取粉丝列表

### 接口地址
```
GET /api/user/{userId}/followers
```

### 接口描述
获取指定用户的粉丝列表（谁关注了我）

### 请求头
```http
Authorization: Bearer <token>
Content-Type: application/json
```

### 路径参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID |

### 查询参数
| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| page | Integer | 否 | 1 | 页码 |
| size | Integer | 否 | 20 | 每页数量 |

### 请求示例
```http
GET /api/user/1998760353125687297/followers?page=1&size=20
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 响应示例

**成功响应**：
```json
{
  "status": "success",
  "message": "获取成功",
  "data": {
    "records": [
      {
        "userId": "1998760353125687298",
        "nickName": "张三",
        "avatar": "http://example.com/avatar.jpg",
        "personIntroduction": "热爱编程，喜欢分享",
        "articleCount": 25,
        "followerCount": 120,
        "followingCount": 80,
        "isFollowing": true,
        "focusTime": "2025-12-10T10:30:00"
      }
    ],
    "total": 120,
    "size": 20,
    "current": 1,
    "pages": 6
  }
}
```

### 业务逻辑

1. **查询SQL**：
```sql
SELECT 
    u.user_id,
    u.nick_name,
    u.avatar,
    u.person_introduction,
    u.article_count,
    u.follower_count,
    u.following_count,
    uf.focus_time,
    -- 判断当前用户是否关注了该粉丝
    EXISTS(
        SELECT 1 FROM user_focus 
        WHERE user_id = #{currentUserId} 
        AND focus_user_id = u.user_id
    ) as is_following
FROM user_focus uf
INNER JOIN user_info u ON uf.user_id = u.user_id
WHERE uf.focus_user_id = #{userId}
ORDER BY uf.focus_time DESC
LIMIT #{offset}, #{size}
```

2. **返回字段说明**：
   - `userId`: 粉丝的用户ID
   - `nickName`: 昵称
   - `avatar`: 头像
   - `personIntroduction`: 个人简介
   - `articleCount`: 文章数
   - `followerCount`: 粉丝数
   - `followingCount`: 关注数
   - `isFollowing`: 当前用户是否关注了该粉丝（互关判断）
   - `focusTime`: 关注时间

## 3. 关注用户

### 接口地址
```
POST /api/user/{userId}/follow
```

### 接口描述
关注指定用户

### 请求头
```http
Authorization: Bearer <token>
Content-Type: application/json
```

### 路径参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 要关注的用户ID |

### 请求示例
```http
POST /api/user/1998760353125687299/follow
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 响应示例

**成功响应**：
```json
{
  "status": "success",
  "message": "关注成功",
  "data": {
    "userId": "1998760353125687299",
    "focusTime": "2025-12-13T23:55:00"
  }
}
```

**失败响应（不能关注自己）**：
```json
{
  "status": "error",
  "code": 400,
  "message": "不能关注自己"
}
```

**失败响应（已经关注）**：
```json
{
  "status": "error",
  "code": 400,
  "message": "已经关注过该用户"
}
```

**失败响应（用户不存在）**：
```json
{
  "status": "error",
  "code": 404,
  "message": "用户不存在"
}
```

### 业务逻辑

1. **验证**：
   - 检查目标用户是否存在
   - 检查是否是自己（不能关注自己）
   - 检查是否已经关注（避免重复关注）

2. **插入关注记录**：
```sql
INSERT INTO user_focus (user_id, focus_user_id, focus_time)
VALUES (#{currentUserId}, #{targetUserId}, NOW())
```

3. **更新统计数据**：
```sql
-- 更新当前用户的关注数 +1
UPDATE user_info 
SET following_count = following_count + 1 
WHERE user_id = #{currentUserId};

-- 更新目标用户的粉丝数 +1
UPDATE user_info 
SET follower_count = follower_count + 1 
WHERE user_id = #{targetUserId};
```

## 5. 检查关注状态

### 接口地址
```
GET /api/user/{userId}/follow-status
```

### 接口描述
检查当前用户是否关注了指定用户

### 请求头
```http
Authorization: Bearer <token>
Content-Type: application/json
```

### 路径参数
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 目标用户ID |

### 请求示例
```http
GET /api/user/1998760353125687299/follow-status
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 响应示例

**成功响应**：
```json
{
  "status": "success",
  "message": "查询成功",
  "data": {
    "userId": "1998760353125687299",
    "isFollowing": true,
    "isMutual": true,
    "focusTime": "2025-12-10T10:30:00"
  }
}
```

### 业务逻辑

```sql
SELECT 
    EXISTS(
        SELECT 1 FROM user_focus 
        WHERE user_id = #{currentUserId} 
        AND focus_user_id = #{targetUserId}
    ) as is_following,
    EXISTS(
        SELECT 1 FROM user_focus 
        WHERE user_id = #{targetUserId} 
        AND focus_user_id = #{currentUserId}
    ) as is_mutual,
    focus_time
FROM user_focus
WHERE user_id = #{currentUserId} 
  AND focus_user_id = #{targetUserId}
```

## 6. 数据库索引建议

```sql
-- 用户ID索引（查询某人的关注列表）
CREATE INDEX idx_user_id ON user_focus(user_id);

-- 被关注用户ID索引（查询某人的粉丝列表）
CREATE INDEX idx_focus_user_id ON user_focus(focus_user_id);

-- 关注时间索引（按时间排序）
CREATE INDEX idx_focus_time ON user_focus(focus_time DESC);

-- 复合索引（优化关注状态查询）
CREATE INDEX idx_user_focus ON user_focus(user_id, focus_user_id);
```

## 7. 注意事项

1. **事务处理**：
   - 关注/取消关注操作需要在事务中执行
   - 确保关注记录和统计数据的原子性

2. **并发控制**：
   - 使用乐观锁或悲观锁防止重复关注
   - 统计数据更新使用 `+1`/`-1` 而非直接设置值

3. **数据一致性**：
   - 定期校验 `follower_count` 和 `following_count` 是否准确
   - 可以增加定时任务修正统计数据

4. **性能优化**：
   - 关注列表和粉丝列表使用分页
   - 添加合适的索引
   - 考虑使用 Redis 缓存热门用户的关注数据

5. **业务规则**：
   - 不能关注自己
   - 不能重复关注
   - 取消关注前需检查是否已关注
