# 文章问答反复回读结果的修复

更新：2026-11-05。

## 现象与原因

文章中的一句话解释请求连续调用 `read_task_result`，多轮决策在 `loaded_context` 校验失败后又读取相同开头，最终触发重复策略保护。

当前请求关联的约 1.1 万字文章被选择性投影为目录，虽然完整请求远低于上下文预算。随后片段已载入，但模型继续使用原始文章任务 ID 作为回答依赖；校验器只接受实际回读任务 ID，因此反复进入修正路径。

## 处理方式

- 当前请求附带的文章或文档参与自适应完整载入；仍检查完整输入预算、历史和图片，不自动展开旧任务或上一运行资料。
- 当模型使用目录来源 ID 作答时，只允许将它关联到本轮实际可见、来源 ID 与版本一致的回读任务。
- 最终回答依赖改为这些回读任务，证据核验仍限制在已读字符范围。隐藏、共享别名、空片段或旧版本不能授予正文权限；引用还必须属于实际回答依赖。
- 保留原有防重复保护和未读资料限制。

## 验证

`python-agent/tests/test_readback_loop.py` 覆盖当前文档载入、预算不足回退、版本与可见性检查、未读尾部隔离、引用归属，以及回读后只需一次模型决策。

相关 156 项回归通过，测试期间没有网络访问。原始问题使用真实模型隔离回放：Main 一次返回回答，未调用回读工具，未触发格式修正；Main 决策阶段约 5.6 秒，此时间不包含后续交付核验。回放没有创建运行或修改用户会话。
