# 写作会话与引用提示线

写作对话在后端标记 `is_writing=1`，已保存草稿通过 `writing_article_id` 关联。列表分为普通聊天、文章问答、草稿写作。公开文章问答继续使用 `origin_article_id`，不会把私有草稿当作公开文章上下文。

浏览器按账号、草稿 ID 记住当前会话选择。重开同一篇草稿时优先恢复该选择；没有本机选择时，后端查询这篇草稿最近的写作会话，因此清除浏览器数据或换设备后也能恢复已保存草稿的最近讨论。历史加载后通过原有运行恢复流程衔接正在生成的回答。读取失败时显示重试入口并禁止发送，避免悄悄新建会话。

未保存文章使用 `new` 作为当前未保存草稿的本机作用域，后端对话已经属于草稿写作，暂不绑定文章 ID；首次保存后同步正式关联，包括保存发生在首次 SSE 返回 ID 之前的情况。主动点击“新话题”会记住本机的新话题选择，不删除历史会话，也不会在重开时又恢复刚刚离开的旧话题。

修复前保存在当前账号浏览器中的确切关联，会在打开 AI 历史或对应草稿时迁移到后端。无法确认来源的旧会话不从标题或正文猜测匹配。私有草稿元信息经 Java 按作者校验，只返回 ID、标题，不读取正文；同一会话不能改绑另一篇草稿或从公开文章问答改为草稿写作。草稿删除或暂不可读时仍保留聊天历史，来源标记为不可用。

数据库新增迁移 `026_writing_conversations.sql`，通过 `python scripts/migrate-product-features.py` 或完整迁移入口执行，启动时检查新字段。RPC 新字段向后兼容，但应先迁移数据库并更新 Java/Python 服务，再使用新版前端。

选中文字引用后，编辑器用 Slate `rangeRef` 跟踪原选区，并在编辑器外层绘制每一行的绿色下划线。多处选区分别标记；移除待发送引用、切换话题或文档时清理对应范围。发送后的标记在当前编辑会话中保留，最多跟踪最近 32 处。编辑其他位置时范围跟随移动；原选区被修改或删除则撤掉失效标记，不搜索同名文字重新定位。

提示线不修改 Slate 文档，不进入保存的 HTML 或撤销历史。刷新后的历史引用保留引用文字，但不凭文字猜测恢复正文标记。范围仅存在当前编辑器实例中，卸载时释放。

验证：`npm test`、`npm run build`，以及 `writing-continuity.spec.ts`、`writing-references.spec.ts`、`writing-assistant.spec.ts`、`editor-tools.spec.ts` 浏览器回归。所有测试使用模拟接口，不调用真实模型。
