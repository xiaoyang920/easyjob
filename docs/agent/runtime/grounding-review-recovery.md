# 核验协议修复与部分交付

核验模型的输出由 `validate_review` 检查。`source_fact + supported` 必须能定位到真实来源：当前协议通过 `evidence_ids` 选择后端生成的摘录目录，旧格式的 `quotes` 仍须匹配实际原文。编号合法不等于事实正确，正文引用与核验所选来源仍须一致。

## 缺少依据编号

当核验结果将来源事实判为 `supported`，却没有支持依据时，后端抛出带安全位置数据的 `ReviewContractError`。这表示核验响应不符合协议，不表示已经判定正文错误。

`review_text` 最多追加一次 `HumanMessage` 格式反馈，包含错误代码、`block_index/unit_index`、原摘录目录的合法编号及修正规则；继续使用相同的正文和资料，不执行工具、不补检索、不修改正文。两个尝试共享原 `GROUNDING_TIMEOUT_SECONDS` 总预算。常识、建议等类别不因该规则被强制要求来源编号。

修正后的完整核验结果重新经过所有原文、覆盖范围、编号和引用绑定检查。没有实际依据时应如实返回 `unsupported/uncertain`，不能编造编号或改成非事实以规避检查。第二次仍无依据、返回假编号或超时则停止格式修复。权限错误、运行预算错误和取消继续向上传播。

这里的格式修复与 `repair_text` 修改回答内容是两个步骤；只有一份合法核验结果确认有内容问题，才进入原有的正文修正流程。

## 长回答分批核验

协议版本 15 保留完整原文及其分段、单元编号，先解析整篇的引用范围，再分批请求核验。单批最多 160 个单元，同一段在每批最多 80 个单元，单篇最多 640 个单元、80 段及 8 批。最多并发 2 批；全部批次及各自最多一次格式修复共用原有核验超时和运行 Token 预算。分批不会自动联网或增加工具权限。

每批必须覆盖它收到的真实编号，不接受遗漏、重复编号或假引文。所有批次完成后再按原文编号汇总，整篇重新检查覆盖范围、引用及安全投影。批次失败或超时会取消并等待其他未完成调用；已完成核验的独立安全段落可以保留。未核验单元明确留作未完成，代码、列表、表格保持原有整体投影规则。已知有问题的原文不会因后续批次失败重新放行。

超过总核验范围使用独立 `review_size_limit`，不再误报为模型返回格式错误；请求发出前被拦截时 `review_calls=0`。`review_batches`、`completed_batches`、`unit_count` 只保存计数，实际格式重试单独计入 `review_format_repair_calls`。前端在回答已生成但核验异常时显示黄色“回答已生成，核验未完成”，刷新恢复历史也沿用这个状态。资料只读到文章节选是另一项范围限制，不等于核验模型认为正文错误。

## 部分交付

核验输入包含 `user_context`：当前用户原话以及带来源的有效要求、已撤销要求和确认决定。准确确认或复述这些要求按 `user_content` 核对，不能因没有公开文章或编辑器文档误删。助手待办不作为用户确认；已撤销项不能恢复，变更原话提到旧值也不代表旧值仍有效。用户原话不证明外部事实，`source_fact` 的真实依据检查保持不变。Main 已分别收到当前消息和任务状态，不重复注入这份核验视图。

“本次检索未找到资料”等通知只针对实际发生的公共检索或选中的公共来源；仅确认任务、读取会话历史时，不再附加并未发生的公共检索结果提示。

草稿核验失败仍阻止审批及保存。普通回答沿用既有降级边界：有已完成核验的安全内容时可保留该部分；已知有问题的原文不能因后续核验服务异常重新放行。

裁剪投影会移除空章节。在前文已删除时，保守移除带“上述／前述／上文”等指代的完整段落；代码块保持完整。编号章节被移除后，保留同级章节的标题文字、去掉失效序号；开头章节被移除时，同时去掉可能承诺完整覆盖的原引言。核验异常提示放在保留内容前。没有裁剪时保持原章节编号。

## 诊断与回归

`grounding_audit.review_calls` 计入实际的批次和格式重试调用；`review_format_repair_calls` 单独记录格式修复次数，`repair_calls` 继续只统计正文修正。`review_contract_failures` 仅保存固定错误代码和位置，不保存核验原文、用户正文或来源摘录。协议版本为 15。

`tests/test_grounding_contract_repair.py` 覆盖缺依据后的修复、二次失败、伪造编号、修正后的再次核验、计数、超时、权限、取消和章节裁剪。全量离线验证：

```powershell
python-agent/.venv/Scripts/python.exe scripts/run-agent-offline-tests.py
```
