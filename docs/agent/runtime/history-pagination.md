# AI 会话历史分页与提问导航

正文与左侧刻度采用不同的数据来源，避免只加载最近消息后旧刻度消失。

- `GET /agent/conversations/{id}/messages?limit=20`：首次加载最近 20 **轮**完整问答；每轮从 user 消息开始，到下一条 user 消息之前结束。`limit` 最大 50，不把问答按单条消息截断。
- `before` / `after`：按 user 消息 ID 向前或向后读取，游标互斥。
- `around`：加载指定提问附近的窗口；提问必须属于当前会话。
- `GET /agent/conversations/{id}/questions?limit=200`：独立的轻量索引，含提问 ID、最多 256 字符的问题和 384 字符的回答预览。用 `after` 和 `snapshot` 分页读完，过程中新增问题不改变原索引边界。

首次打开只请求最近正文，导航索引独立加载。点击未加载的旧问题时替换正文窗口，再按 ID 滚动到提问；窗口底部可加载后续消息或回到最新。向上滚到边界或点击顶部按钮加载更早消息，前插后恢复滚动高度差，保持阅读位置。

DOM 使用稳定的 `itemId`；提问用字符串 `messageId` 定位，避免 Snowflake 转 Number 丢精度。SSE 通过 `__INPUT_ID__` 返回新提问的数据库 ID。流式回调绑定响应式消息对象，页面加载历史或跳转窗口不会改变回复目标。浏览旧窗口期间暂停自动贴底；发送新问题前先同步最新窗口。

失败运行只投影到本页包含的轮次，并只读取这些运行的活动记录。待审批草稿只附加到最新窗口。Java 转发使用登录用户身份，Python 在读取正文与索引前均校验会话归属。

不带 `limit` 的原消息接口保留兼容；新的聊天页面使用分页。此处调整页面历史展示，LLM 上下文仍由原有 Token 预算与增量摘要策略管理。

验证：`frontend/tests-e2e/history-pagination.spec.ts` 覆盖 100 轮会话、全部刻度、悬浮预览、定位与滚动锚点、生成中翻页；`scripts/agent-history-page-check.py` 使用隔离本地数据验证真实 MySQL → Python → Java HTTP 链路、权限和失败运行投影，结束清理测试记录，不调用模型。
