# 工具调用校验与任务内修复

Main 的动作契约修正、只读工具调用修正和依赖服务重试是三个不同边界。

- Main 决策不符合格式、任务权限或依赖契约时，原有决策层提供结构化错误，并限次重新决策。
- `run_tool_agent` 的只读工具循环检查工具名、JSON Schema 和参数范围。缺参、类型错误、非法 JSON、允许工具名的明确拼写错误，通过带原 `tool_call_id` 的 `ToolMessage(status="error")` 返回模型。每个任务最多进行一次修正，而非每个错误分别无限重试。
- 网络超时、限流和服务故障由原依赖客户端负责有界重试。工具循环不把网络异常交给模型改参数，不额外叠加网络重试。

工具必须同时满足任务传入的工具白名单、后端只读策略和执行上下文能力。MCP 的 `readOnlyHint` 不授予权限；同名 MCP 工具不继承本地工具权限。权限拒绝、用户取消、失效执行令牌、审批和业务版本冲突继续向上抛出，不进入参数自修复。

一次批量调用先完成整批权限检查，再执行。工具成功结果按名称与参数在当前任务内复用，模型修正时重复提交成功调用不会再次请求工具。结果使用本次调用的新编号返回，保持消息协议配对。缓存不跨请求、不保存写操作。

修正仍失败、放弃修正或工具不可用时抛出安全的 `ToolTaskError`。委派执行层将它记为当前任务的 `tool_error`，将错误代码、工具名和修正次数同时写入 `task_results.tool_failure` 与 `observations.tool_failures`，Main 在现有轮数与策略修正上限内处理。成功的独立任务继续保留，依赖失败结果的任务记为 `blocked`，不会执行。未知程序错误不会伪装成可恢复的工具错误。

当前主流程的检索由受控检索管线执行；分析、检索后生成和写作仍以 `tools=[]` 消费已声明资料。本次没有让这些生成任务获得自由检索或保存文章的权限。该修复机制用于共用工具循环中经后端明确授权的只读调用，草稿保存仍经过独立审批入口。

离线覆盖参数修正、工具名拼写、非法 JSON、权限拒绝、成功调用复用、修正上限、超时、取消、执行令牌、调用编号注入、指标回调，以及失败依赖阻断。`scripts/tool-recovery-smoke.py --live` 可用公开合成资料和真实模型验证一次参数修复，不读取用户资料或修改会话。
