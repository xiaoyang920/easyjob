## 发现的问题

### 1. 创建运行记录发生MySQL死锁

全量运行的 `ambiguity-04` 在首轮创建运行时失败。
服务日志定位到 `app/services/run_repository.py` 的 `create` 中，`INSERT INTO agent_run` 返回MySQL错误1213。
此前并发2的12场景抽样还出现两次同类错误。需分析运行创建事务及索引锁范围，不能把这个错误计为模型回答质量问题。
评测没有自动重试并擦除第一次失败，也没有修改应用事务来提高通过率。

2026-10-03 后续定位及修复：InnoDB 死锁记录显示两个创建事务持有
`idx_agent_conversation` 的 `supremum` 间隙锁，同时等待插入意向锁。
保留会话行锁与活跃运行唯一约束，将创建流程改为非加锁查询活跃记录；
仅在记录存在时按主键加锁、核验状态并处理过期，不再对空运行范围执行更新或加锁查询。
隔离级别仍为 REPEATABLE READ；1213 最多尝试3次完整创建事务，保持请求幂等键，不重跑AI流程。

真实数据库专项回归：旧逻辑在两个临时会话中复现1次死锁；新逻辑200个不同会话、
并发10且禁用重试，200次创建成功、0次死锁；同会话10个并发请求仅创建1条运行，
其余9个返回409。幂等重放、过期替换、旧执行隔离、待审批及已保存草稿保护均通过。
专项报告：`logs/evaluation/run-concurrency-20261003-185805.json`，临时数据已清理。
相关50项离线测试通过，Python服务已重启并通过健康检查。
此专项回归不重新计算原136场景通过率；该次修复时问题2与3尚未处理。

### 2. 旧版本审批冲突在Java层变成500业务错误码

全量6个修改草稿场景均发现：Python `/chat/resume` 返回409，Java转发后的响应为500业务错误码。
`AgentService.post` 的 `RestTemplate` 异常被全局通用异常处理捕获，没有保留原冲突语义。
全量首版检查在状态码不符时停止该场景，故这些场景没有完成后续的合法审批。
原始数据与当时脚本快照均保留，不按后续脚本重新解释为成功。

追加12个草稿场景补测：`logs/evaluation/scenarios-draft-verification-20261003/`。
完善后的脚本分别检查冲突错误码、账本等待状态、是否误保存；仅错误码不符时继续检查合法批准/拒绝。
已记录的6次旧版本批准探测中，账本都保持等待审批，未发生误保存；后续合法审批可完成。
因此当前证据是**冲突错误码传递有问题**，不能写成“旧版本审批绕过保存保护”。

### 3. 草稿结构化输出超长导致生成失败

追加补测的 `draft-05` 生成时，模型输出的summary超过120字符，`DraftOutput`校验抛出ValidationError，接口返回500业务错误码。
需要为这种结构化输出格式失败补上有界修正或明确降级；当前评测只记录问题，没有修改业务实现。

## 后续审批与摘要修复（2026-10-03）

保留原始全量及补测结果，另行验证修复后的实现：

- Java 同步与流式代理保留上游业务冲突状态，统一异常处理同时返回HTTP 409和业务code 409；
  前端SSE读取错误响应中的消息，提示重新加载会话后确认，不再把旧审批冲突显示为系统500。
  上游5xx统一返回安全的502提示，不向浏览器透传内部错误体。
- MySQL `article_info.summary` 本身为VARCHAR(500)，无需修改表。
  Python模型、结构化提示词、Java保存校验及编辑页统一为最多500字符，建议生成150～300字符。
  Unicode摘要的Python与Java校验均按字符码点计算。
- 结构化输出的校验或解析失败只增加1次修正调用，不重新执行写作或检索；
  再次失败后从原Markdown提取标题及不超过300字符的摘要。
  原Markdown正文保持原样，摘要在审批及hash生成之前确定，保存时不改变已审批内容。
- 7项摘要测试、15项图与审批回归、21项Java代理及保存边界测试、14项前端协议测试通过；
  前端类型检查与构建通过，Java/Python服务已更新启动并通过健康检查。
- 真实模型专项复测：12个草稿场景全部通过，覆盖生成、拒绝、修改、旧审批冲突与批准保存。
