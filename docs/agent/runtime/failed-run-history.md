# 失败运行的历史与继续执行

## 用户看到的行为

- 失败、超时、停止的轮次保留在原提问之后；刷新页面或继续发起新问题，都不会覆盖旧失败记录。
- 活动面板恢复原来的完成步骤、失败步骤和运行耗时。失败面板默认展开，可手动折叠。
- 在同一会话发送“继续”时，Main 能看到最近运行的原提问、停止节点、任务状态及经过核验的只读结果候选。它在原有 MainDecision 中选择哪些结果适用于当前目标。
- 无关新问题可以不选择任何旧结果。继续执行不等于恢复上次模型输出到一半的 token 流。

## 存储与接口

复用已有表，无需数据库迁移：

| 数据 | 存储 | 用途 |
| --- | --- | --- |
| 用户提问、成功回答 | `ai_message` | 正式对话消息 |
| 运行状态、输入锚点、节点进度 | `agent_run.result_json` | `user_message_id` 关联原提问，`progress` 保存有界恢复投影 |
| 节点开始、结束、失败 | `agent_run_event` | 进程中途退出或细粒度事件清理后的回退记录 |
| 流式活动、计划、说明 | `agent_stream_frame` | 还原活动面板；不把未提交的局部回答当成成功答案 |
| 只读子任务产物 | `agent_task_artifact` | 委派中某任务已成功、整个节点尚未返回时，也能保留成功产物 |

读取历史时，Python 将失败运行投影成带有 `runId/runStatus/agentEvents/runStartedAt/runFinishedAt` 的助手记录，Java 使用 `AiHistoryMessageVO` 保留这些字段，前端用同一活动归约器恢复面板。投影不再向 `ai_message` 插入一条假成功回答，也不递增会话消息计数。

新运行在图片预处理前保存提问和输入锚点，因此图片处理失败也能关联到该提问。旧运行没有锚点时，只能按邻近提问时间尽力匹配；若既无流事件也无节点记录，就无法还原从未持久化的步骤。

`progress` 和输入锚点仅供后端恢复，不在运行详情的 `result` 或聊天响应中返回。读取历史与恢复候选均验证会话归属。会话无权限时返回 404，不暴露上游错误正文。

## 下一轮如何使用

1. 请求入口读取最近运行。普通成功回答不会导致更早的失败重新进入恢复上下文。
2. 对失败、过期、取消的运行读取节点记录、进度以及部分完成的委派产物。
3. 只将成功的公共检索/分析产物作为候选；不自动导入私有草稿、记忆结果和保存动作。
4. 平台文章回查 MySQL，校验公开状态、访问条件和正文哈希；无哈希的文章来源不能跨轮复用。网页资料超过一天不再作为复用候选。连续重试仍保留原始网页时间，不能靠重试刷新资料年龄。
5. `previous_run.reusable_results` 最多提供 4 个完整产物，总序列化大小约 24,000 字符；超过预算就不提供该产物，不截断正文假装完整。新完成产物优先保留。
6. Main 在同一次结构化决策中填写 `reuse_previous_results`，并可通过 `answer_dependencies` 或新任务的依赖引用选中的结果。后端检查 ID 存在且不重复，之后才合入 `task_results`。没有新增 action，也没有额外的“选择是否复用”模型调用。
7. 连续继续仍按同样预算保存选中的只读产物，保留原来源身份。继承产物不占用本轮新执行任务数量，但占用完整输入 Token 预算。

`saved_draft_id` 存在意味着保存已经提交：恢复上下文只提示该事实，不重放写操作。若需要修改，仍须读取当前草稿版本并重新经过审批。

原有的同一运行只读委派恢复保持独立：只有通过 Checkpoint、执行代次与任务契约校验的候选才能使用恢复入口，且受原有次数限制。普通“继续”创建新运行，由 Main 选择策略，不承诺所有节点都可原地重启。

## 验证

- Python：`python-agent/tests/test_run_history.py` 覆盖历史顺序、活动时钟、旧数据回退、失效来源、连续继续、候选选择、伪造 ID 拒绝和输入预处理失败；`test_run_repository.py` 验证审批/结算保留输入锚点与进度。
- Java：`AgentProxyTests` 验证运行字段、活动和时钟穿透消息接口，以及无权限的 404。
- 前端：`agentStream.test.mjs` 验证活动恢复；`tests-e2e/agent-run-history.spec.ts` 使用隔离接口夹具验证真实页面刷新和失败面板。
- 本地集成：在仓库根目录运行 `python-agent/.venv/Scripts/python.exe scripts/agent-run-history-check.py`。脚本使用真实 Java HTTP、MySQL、Redis，创建隔离用户与数据，验证历史、用户隔离、来源变更、事件回退，并清理自己的夹具。报告写入 `logs/evaluation/agent-run-history-*.json`。

以上恢复验证不调用真实模型，不应作为模型选择正确率或模型续写质量指标。
