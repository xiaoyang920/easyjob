# 运行管理与索引对账

管理员打开 `/admin?section=operations`，查看任务队列、AI 运行和阅读量同步积压。接口只返回标识、状态、尝试次数和经过过滤的错误码，不返回对话、任务 payload、结果或执行租约。每个接口重新校验数据库中的管理员身份。

只有 dead 后台任务允许重试，事务内锁定主键、核验状态、清理旧租约并记录审计。普通 AI 运行没有一键重跑入口，避免重复草稿保存等业务操作。已退役的 memory_extract 不能恢复。

MySQL 是权威数据源。后台在任务队列空闲时进行低优先级对账，每批最多 20 条，文章/记忆主扫描约 10 秒后暂停并保存游标；单次最大 80 秒，租约 120 秒。未完成扫描一分钟后继续，完成一轮后十五分钟再检查。管理员可以提前安排下一批。游标完成和错误记录都要求租约 token 与期限仍有效。

对账分为文章内容/分块、决策记忆、已删除文章、已删除记忆和残留向量分块。分块残留使用按 article_id 的 composite aggregation，覆盖正文索引已经不存在的情况。所有修复都通过已有 outbox 或 memory_index 队列执行；入队前锁住原记录再次比较版本。存在 pending/running/dispatched/dead 修复任务时不重复创建，避免绕过重试上限。阅读量只提交单调合并任务，不重新生成向量。

新生成的分块带 chunk_count，可以检测最后一块缺失。老分块兼容读取：检查正文 hash、chunker_version 与序号连续性，不因缺少新字段自动重做付费 Embedding；旧分块只有最后一块缺失的情况，需在文章下一次重建后获得总数校验。对账的“提交修复”计数表示入队次数，不能当作修复完成或准确率。

清理每分钟检查一次，最多四批、每批五百条，并设循环时间预算。删除前重新检查状态和保存期限，保留待审批的运行、流数据和检查点；completed 任务保留三十天，dead 任务保留九十天。阅读计时只清理三十天前已被新会话替代的记录，保留当前 active_session。阅读去重回执保留原有两天规则。

推荐多样性只调整一页内最多五个排序位置，优先减少同作者/同分类连续超过两篇；缺少替代内容时保留原有文章。可读与未解锁两个区段保持分离，不改变分页总数、阅读门槛或分类筛选。该策略没有宣称点击率提升，需要真实曝光和点击数据才能衡量效果。

新增 014 迁移可重复运行，并检查文件校验和。先执行迁移，再启动新 Agent；启动时检查维护表字段，缺失时给出明确迁移提示。检查脚本使用临时数据，不请求模型或 Embedding；旧评测报告保留，当前测试口径见 evaluation/README.md。
