# 上下文管理：模型视图、任务状态与原文回查

## 数据职责

- 原始会话保存在 MySQL `ai_message`；摘要与游标仍在 `ai_conversation`。
- 完整任务结果继续保存在现有、按 run 隔离且受执行代次保护的 Redis Checkpoint `task_results`。本次没有迁移结果到新表，也没有删除旧 Checkpoint 字段。
- 模型视图由 `context_projection.py` 构建。缩减视图不修改 Checkpoint 原始结果。现有最终交付核验仍读取原始证据。
- `task_context` 保存带来源的任务要求、撤销、确认决定、助手提出的待办，以及服务端从成功任务生成的完成记录。它随 Checkpoint 恢复，并通过现有 MySQL `agent_run.result_json` / `progress` 传递到下一轮；不授予权限，不自动写长期记忆。

## 预算与选择

`AGENT_CONTEXT_TOOL_INLINE_TOKENS` 默认 32768。小结果集合保持原样；超过软预算时优先放入最近结果，其余公开结果显示 `index_only`、大小、来源索引和回读入口。字节相同且引用元数据相同的结果可以通过 `shared_result/same_as` 共享已载入正文，不合并不同引用或不同版本。

`AGENT_CONTEXT_RESULT_ACCESS_ENABLED` 默认开启，启用按步骤选择结果。`AGENT_CONTEXT_RESULT_SMALL_TOKENS` 默认 8192：小结果在结果软预算内直接载入；较早的大结果保持目录。后台实际刚完成的 `action_task_ids` 对应结果可在完整请求预算允许时扩展，避免新检索立即再绕一次读取。上一轮可复用结果不因有空间就全部重新带入；私有必要资料和最近主动读取的结果仍受保护。

`AGENT_CONTEXT_TOOL_ADAPTIVE_INLINE` 继续控制额外空间准入。完整请求计入历史、图片、系统提示及 Schema，低于压缩触发点和硬输入上限且保留 1024 Token 余量才扩展当前结果，不挤掉历史；字符上限生效，刚压缩的当前轮不重新撑破 64K 目标。回答依赖按实际发给模型的视图验证。关闭 `AGENT_CONTEXT_RESULT_ACCESS_ENABLED` 可退回之前“放得下就全部带入”的自适应方案；再关闭 `AGENT_CONTEXT_TOOL_ADAPTIVE_INLINE` 可复现固定 32K 投影。读取器的新增接口为兼容性扩展，策略回退不删除原始结果。

私有原文及其派生分析保持明确的必要输入，不通过公开结果读取器回读。必要资料超过总预算时仍由既有硬门禁终止，不静默截断。Main 的执行事实不再重复注入编辑器和普通公开工具正文；交付核验保留完整版本。

`AGENT_HISTORY_LOAD_MAX_TOKENS` 默认 196608（192K），与 256K 总上下文、192K 压缩触发点配套。数据库按 64 条向前分页，达到软预算后在完整轮次边界停止。超长单轮保留整体，最终请求门禁决定是否接纳。旧范围未载入时显示 `history_notice`，不声称摘要覆盖所有历史。

普通历史压缩仍按全请求阈值触发。存在分页缺口时，只读取摘要游标之后、缺口之前的最早一页，排除可能未读完的末轮，再压缩连续旧前缀。游标只能推进到实际压缩完成的位置。失败、过期写入、空摘要或无可处理前缀均不能跨缺口推进游标。

摘要超过输出预算时最多追加一次重新压缩，共享原有调用次数和时间上限；仍不合格则保留原文与旧游标，不截断摘要末尾。原始用户消息和图片上传事实仍保留。

`AGENT_SUMMARY_INPUT_MAX_TOKENS` 默认 262144（256K），与本地运行配置一致。摘要打包同时遵守共享上下文的输出及安全预留；约 21 万 Token 的历史无需再因旧的 32K 配置拆成多次摘要调用。压缩触发点仍为 192K，压缩后总上下文目标仍为 64K。

## 工具与权限

Main 仍只有 `answer/call_tool/delegate/write_draft` 四种动作。四个 Main 专用上下文只读工具，不向委派执行器或 MCP 授权：

| 工具 | 范围 | 服务端检查 |
| --- | --- | --- |
| `read_task_result` | 当前 run 已取得的公开只读结果，按字符范围回读 | 结果类型、私有派生标记、公共来源版本、联网开关与当前约束 |
| `read_task_results` | 一次最多读取 4 份当前运行公开结果，整批共享 24K 字符和半个 worker 输出 Token 预算 | 每项检查来源、权限、版本；全部通过后才返回，不能用合法项掩盖非法项 |
| `search_conversation_history` | 当前用户当前会话，关键词和消息游标分页 | 会话归属、参数化查询、转义 LIKE 通配符、数量上限 |
| `read_conversation_messages` | 当前会话的指定消息 ID，按字符范围读取 | 会话归属、所有 ID 均属于当前会话、数量和单条长度上限 |

工具参数不接受 user_id/conversation_id/run_id。身份来自后端执行上下文。私有草稿、记忆和编辑器继续使用专用读取工具。公共文章有版本变化时拒绝回读，要求重新检索；网页回读只是原快照，不构成新鲜联网查询。

结果回读支持字符范围、`query` 字面关键词上下文、`citation_id` 三种方式。两个定位参数互斥，定位直接返回原文片段，不先支付一次模型调用只找位置。没有命中时返回 `matched=false`，不给空命中授予引用。普通回读直接读取执行器传入的当前 `state.task_results`；公共来源的权限／版本重查仍可访问业务服务，LangGraph 自身的持久化和恢复 I/O 也继续存在。

每个新回读结果携带后端 `result_reads`：原始来源 ID、稳定版本摘要、正文或引用字段、字符范围和引用 ID。Main 视图按已载入范围减去重叠片段，不修改保存的原文；回读别名解析到原始来源并逐跳检查权限。旧检查点缺少元数据时按旧格式读取，旧范围任务缺少新增可空参数时安全补默认值。交付核验使用实际读取片段对应的来源范围，不能拿仓库中尚未读到的尾部为回答背书。

`AGENT_CONTEXT_READ_MAX_CALLS` 默认 6。回查拥有独立次数上限，不占业务任务名额；累计 Token 预算、硬请求预算和只读失败恢复次数仍生效。Main 必须先回读被省略的回答依赖，不能直接把索引当成正文。需要完整原文的分析任务可显式声明原始任务依赖，后端仍加载完整依赖。

## 任务状态真实性

`task_context_patch` 是可选控制字段；新目标、要求和确认决定必须逐字匹配当前用户原话。撤销必须指定已有要求 ID，并引用当前用户的变更原话。修改已有要求需要先撤销，不能覆盖同 ID 的不同内容。助手待办、问题明确标注 `agent_proposal`；模型不能提交“完成记录”，完成记录由实际成功任务生成。

这些检查验证原话来源与执行来源，并不等于已证明模型对所有自然语言的语义理解正确。当前用户原话、长期有效约束和原始执行结果仍作为判断依据。

## 可观测性和验证

上下文记录系统提示、历史、工具结果、记忆、任务状态、当前输入及图片等本地 Token 估算，以及未载入标记。计数不保存提示词正文；真实供应商用量仍以已有 `RunMetrics` 为准。

回归覆盖：原始结果不变、结果回读分段、私有及私有派生拒绝、联网禁用/用户拒绝、来源变化、历史跨会话读取、通配符、撤销要求、分页缺口、摘要游标、超长摘要重压缩和恢复。旧预算与压缩测试显式关闭结果视图的软预算，继续独立验证硬预算保护。

离线模型替身可以验证流程和权限，不能证明真实模型的长期语义保真率或响应质量。发布后的真实长对话还需对比：要求保留率、原文回查命中率、引用正确率、任务完成率、响应耗时和实际 Token。

2026-10-23 的真实模型和网站 HTTP 验证、失败样本、修复及性能代价见 [真实调用验证](36-context-live-validation.md)。

## 第二阶段补充（2026-10-26）

同轮构建复用由 AGENT_CONTEXT_BUILD_CACHE_ENABLED 控制，默认开启。缓存只保存最多 512 个数值计数，完整/精简模型视图共享结果归一化和来源摘要，不跨用户/运行保存正文，也不缓存业务权限。

结果读取增加 queries（最多 5 个字面关键词，任一命中）、section_id 和绑定来源版本及定位条件的 cursor。最多 32 个明确 Markdown 章节进入目录；后续命中使用 next_cursor 继续。批量预算先排除空命中并回收短结果余量，完整返回的包装、引用及范围元数据共同遵守输出预算。旧参数、旧检查点可空默认值及旧任务策略指纹兼容。

AGENT_CONTEXT_RESULT_PREFETCH_ENABLED 默认关闭，本地经过配对验证后开启。首次决策遇到明确的已有平台公开结果与原文关键词/引用时，可预读最多两份、共 4096 估算 Token 的片段；私有资料、网页、否定读取、已载入或含糊来源跳过。没有明确旧来源时不额外渲染请求。普通结果读取与预读共用权限和版本检查，回答及 Main 派生分析沿用实际可见范围，重复依赖的范围元数据取集合。

RunMetrics 增加有界的 context_builds、token_calibration，分别记录本地准备计数及每次调用的估算/实际输入配对；不记录正文和关键词。自动 Token 校准保持观察模式，256K 总量、192K 触发点、64K 目标及安全预留不变。
