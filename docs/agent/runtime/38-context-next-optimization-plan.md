# 上下文管理下一阶段改进计划

状态：已实施并完成本地验收；Token 校准保持观察模式。制定日期：2026-10-25，验收日期：2026-10-26。结果、开关、失败样本和验证边界见 [实施与验收](39-context-next-validation.md)。

前置成果及基准见 [结果读取验收](37-result-access-validation.md)。本计划接着优化已上线的按需读取方案，不重做存储架构。

## 目标与范围

按顺序解决三个问题：重复组装上下文的本地开销、长结果定位不便、明确追问旧资料时多一次模型决策。同步完善 Token 估算校准和长期运行验证。

维持现有约定：

- 完整结果保存在 AgentState.task_results；普通读取访问当前状态，Redis Checkpointer 负责持久化与恢复。MySQL 的会话、运行账本和审批职责不变。
- 总窗口 262144、压缩触发点 196608、压缩后整体目标 65536 保持用户已确定的配置。
- 模型只见目录不算读过正文；回答和核验只能使用实际可见的来源范围。
- 用户、会话、运行与执行代次由后端提供；缓存、索引和游标均不授予权限。
- 不新增向量库、结果数据库、摘要模型调用或公共读取器的私有资料权限。

实施顺序：P0 基准 → P1 同轮计算复用 → P2 定位与分页 → P3 有条件预读 → P4 预算校准 → P5 综合验收。每阶段独立验证；P3 未达到收益门槛时保持关闭，不阻塞其他改进交付。

## P0：冻结基准，补齐耗时分解

修改位置：services/run_metrics.py、services/main_context.py、graph/main_agent.py、evaluation/context_live.py，以及独立的上下文构建性能脚本。

工作内容：

1. 记录当前源码版本及相关文件摘要、模型标识、配置和输入夹具。后续按阶段保存报告，不覆盖 37 文档的原始结果。
2. 在已有模型用量和 context_views 指标上增加有限的分阶段计数：上下文准备时间、结果哈希次数、Token 计算次数、读取/预读次数与命中状态、实际返回片段量。不要把嵌套计时简单相加当成总耗时。
3. 读取耗时区分来源权限/版本查询、本地定位和模型决定读取的时间。指标不保存正文、用户关键词、凭证或完整提示词。
4. 基准覆盖：新小结果、旧长结果尾部、两份旧结果比较、当前完整长结果，以及大量重复关键词和零命中。

验收：冻结基准能重复运行；实际模型统计与本地估算分列；对照清楚标注是同代码策略切换还是冻结实现对比。现有 24 个样本是每场景每策略两次，不据此作 P95 或稳定性结论。

## P1：复用同一轮上下文的派生计算

修改位置：graph/main_agent.py、services/context_projection.py、services/result_access.py、services/main_context.py、utils/context_budget.py；必要时增加一个小型派生视图模块。

已确认的问题：main_message_renderer 会分别调用 decision_context 构建精简和完整视图，重复归一化及计算原始结果版本；历史准入、压缩评估和最终门禁又会多次序列化与计数。

实施方式：

- 每次 Main 决策创建一个作用域明确的只读构建上下文，归一化结果、计算版本、生成目录各做一次；完整/精简视图共享这些派生值。
- 同轮复用不变消息、Schema 和结果视图的 Token 估算；缓存键覆盖实际序列化内容及估算器版本。正文视图经过引用过滤、片段去重后必须重新计数，不能用原始结果的计数代替。
- 不只凭 task_id、可变 dict 的对象地址或模型提交的 source_version 判断相同。构建期间固定快照，进入下一决策或恢复进程后重新建立作用域。
- 首期不加全局跨用户正文缓存，也不持久化缓存。缓存释放跟随本轮构建生命周期，避免为了省 CPU 重复保存大段正文。
- 权限、来源版本有效性、执行代次检查不缓存。结果哈希用于内容定位，不能代替业务来源校验。
- 保留完整请求的最终门禁；不能把分项 Token 数简单相加后当成精确的整体 BPE 计数。

验收：

- 开关前后发送的消息内容、选中结果、读取范围及预算判断一致。
- 测试新增结果、正文变化、引用变化、同 task_id 不同运行、压缩后重建、旧 Checkpoint 恢复均不会复用陈旧值。
- 长结果夹具中，同一次准备流程内每个不变原始结果只生成一次版本摘要；对多个规模各运行至少 30 次本地计时，报告中位数、分位数和内存变化。
- 仅在实测显示计算减少且未引入无界缓存后默认开启。不给出未经实测的端到端加速承诺。

## P2：完善定位、分页与批量预算

修改位置：models/main_tool.py、services/result_access.py、services/context_tools.py、graph/staged_plan.py、graph/main_agent.py、tests/test_result_access.py。

继续使用 read_task_result/read_task_results，不再添加近似功能的工具。

### 参数与读取行为

1. 保持旧 source_task_id/start_char/max_chars/query/citation_id 的含义。
2. 新增可选 queries，最多 5 个去重字面关键词，每项最多 200 字符。首期采用“任一关键词命中”，不是正则、语义搜索或额外联网；query 与 queries 互斥。
3. 新增可选 section_id。目录仅从明确存在的 Markdown 标题等可靠结构生成；记录原文范围，不把普通粗体或自然语言猜成章节。没有可靠结构时继续用关键词或字符范围。
4. 新增可选 cursor，用于继续读取后续命中或过长章节；与非零 start_char 不混用。查询、引用、章节定位模式继续互斥。后端把游标绑定到原始任务、内容版本、字段、定位条件和读取进度。
5. 游标有长度上限、严格解析及越界检查；版本或定位条件不匹配时明确要求重新定位。游标不是授权令牌，每次仍从当前可读 task_results 解析来源并检查权限。
6. query 的返回片段仍有数量和预算上限，但必须能通过 next_cursor 访问第 4 处及更后的命中。输出区分没有匹配、仍有后续匹配、正文片段被预算截短，不用一个含糊的 has_more 混在一起。
7. 所有范围使用与现有读取器一致的 Python 字符偏移。多关键词窗口重叠时按来源范围合并；分配窗口时优先容纳完整命中词及周边原文，正文不得改写。
8. 章节索引与目录也受 Token/条目预算约束，不能把整篇文章的目录无限展开。目录本身不授予正文证据权限。

### 批量行为

- 仍最多 4 项，整批共享 24000 字符及当前读取 Token 上限，先完成全部来源授权与有效性检查。
- 两阶段分配：先确定哪些项有内容及各自需求，再分配片段预算；空命中和短结果未使用的预算可以补给被截断的项。
- 正文、JSON 包装、引用和读取元数据共同遵守现有工具输出门禁；不只检查正文长度。
- result_reads、原始来源版本、实际可见范围与交付核验保持贯通；后续分页不把旧范围伪装成新来源。

### 兼容与验收

- 旧参数和旧 Checkpoint 缺少新增可空字段时补默认值；不放宽额外字段或身份字段检查。若持久化任务指纹包含参数，兼容旧默认值需同时覆盖指纹及重复执行判断。
- 回归：单词重复 10 次逐页可到达、零命中、多关键词窗口重叠、超长章节、重复标题、中文/emoji/换行偏移、恶意或过期游标、四项中一项非法、批次中空命中预算回收。
- 原始结果逐字不变；每个返回片段可通过 result_reads 在原始结果中精确重建；未读部分仍不能支撑回答。

## P3：明确来源的小片段预读

修改位置：graph/main_agent.py、services/main_context.py、services/context_projection.py、services/result_access.py、services/context_tools.py、services/grounding.py；新增小型 result_prefetch 服务。

目的：对用户明确追问已有资料的情况，减少“模型先提出读取 → 读取 → 模型再回答”中的一次决策。预读只检索已授权结果，不触发新检索、额外摘要模型或业务写入。

### 触发规则

- 首期只处理平台公开资料。必须能从本轮明确引用、来源标识或无歧义的原文引用映射到当前运行允许读取的来源。
- 前端来源标识若有传递，也只是线索；必须由后端与当前可读来源对上，不能据请求参数直接加载其他运行数据。
- 明确来源之后，可使用本轮用户逐字给出的关键词/引用进行定位。单独一个宽泛关键词、“继续”“上次那个”、多个同名来源、私有资料、网页快照一律不自动预读，交给现有 Main 工具路径。
- 若来源正文已经载入、现有片段已覆盖目标，跳过预读；无命中不伪造摘要。

### 预算与证据接入

- 每个用户轮次首次 Main 决策最多预读 2 个来源，新增正文和元数据合计最多 4096 估算 Token，且必须满足完整请求预算。
- 预读仅使用保留用户要求、近期完整轮次和当前必要结果后的剩余空间；不为了预读触发压缩或删掉这些内容。空间不足时缩小或跳过。
- 预读前复用来源权限/版本验证和取消/代次检查。失败只令预读跳过，未经验证的片段不能流入模型。
- 将片段作为原任务的部分视图，携带相同的 result_reads 和 source_version；不伪造一个成功执行的 Main 工具任务。
- Main 依赖检查、产物生成和 answer_source_scope 都依据实际发出的视图，不能因原 task_id 存在就取回全文用于背书。
- 恢复后从当前状态重新确定是否准入预读，不能把缓存当作恢复依据。最终回答的可见范围仍按现有机制保存。
- 单独记录 attempted/hit/skipped 与原因、额外 Token、避免的显式读取次数；日志不存关键词和正文。

验收与启用：

- 新增独立配置开关，初始关闭。命中、歧义、无命中、权限撤销、资料更新、预算紧张、已有覆盖、压缩后状态分别验证。
- 同一输入、同一模型做预读开/关配对，交错顺序，每类至少 10 对；回答质量、来源范围和引用正确性不得下降。
- 明确来源场景应减少一次模型决策；无关场景不新增模型调用。必须报告实测延迟和输入 Token，额外预读超过既定预算或未带来稳定收益时保持关闭。

## P4：用实际用量校准 Token 估算

修改位置：services/run_metrics.py、utils/token_utils.py、utils/context_budget.py、app/config.py、.env.example，以及 evaluation 下的校准报告脚本。

当前 cl100k_base 是预算估算器，不等于 DeepSeek 的实际分词器。此次先建立校准证据，再决定是否增加保守修正。

- 按每次调用配对保存本地完整请求估算、供应商实际 input_tokens、模型标识、图片有无和有限的结构计数；不保存原文，不将缓存折扣后的计费量当成窗口占用量。
- 使用受控中文、英文、代码、混合、工具 Schema 和图文夹具分组；遗漏用量或失败调用单独统计，不填成 0。
- 校准系数必须绑定供应商/模型及估算器版本。首期只评估影子数据，不在线自行降低安全余量，不因少量样本自动扩大可接纳输入。
- 若确认持续低估，使用经验证的保守倍率或附加余量；统一应用于 Main 准入、摘要打包及运行预算预留，保留原始估算和实际值供核对。
- 总量 256K、触发点 192K、目标 64K 不修改；现有输出、安全预留和字符硬限制继续生效。

验收：边界夹具验证准入/拒绝一致，缺失统计不破坏预算，模型切换不误用旧校准；实际估算差异、样本量及建议值写入报告。没有充分样本时交付指标与报告，修正策略保持关闭。

## P5：综合验收、恢复和上线

### 离线回归

围绕本次改变执行结果读取、Main 消息构造、压缩、硬预算、来源权限、grounding 和 Checkpoint 兼容测试。通过后跑一次完整离线回归；没有新变更或失败时不重复整套运行。

### 真实模型与网站链路

- 读取场景覆盖新结果直接回答、旧尾部、批量比较、多关键词、分页后部、全文分析、明确来源预读和模糊追问。
- 配对对照固定输入/模型并交错执行顺序，记录正确率、引用范围、模型调用次数、读取次数、供应商输入/输出 Token、端到端耗时和上下文准备耗时。
- 小样本只报告样本分布；P95 作为探索性指标需至少 100 次同类受控请求并标注规模，不宣传为服务 SLA。
- 长对话验证保留用户要求、撤销旧要求、否定条件、代码精确值和引用；检查压缩游标连续，摘要不能恢复已撤销要求。
- 实际路径必须包含网站 → 网关 → Java → Agent → 真实模型，并检查业务账本和持久化结果；模型直调、组件图和 HTTP 测试分别报告。

### 故障与并发

- 只读任务在读取前、读取后、Main 回答前受控中断，跨进程恢复后验证已完成结果不重复执行，游标/范围/要求仍一致。
- 长对话完成压缩后重启，验证摘要及游标持久化、原消息可回查和回答来源范围。
- 写作任务只走现有审批恢复入口；检查等待状态保持、拒绝不写入、确认只提交一次。普通失败恢复入口继续拒绝写作/审批状态，本计划不扩大自动恢复权限。
- 同一运行同时提交恢复请求时仅一个执行代次生效；不同运行分别以 1/2/4 并发测延迟、内存、依赖连接及状态隔离。
- 所有故障注入和写入测试仅使用独立测试账号、资料、草稿和运行，不中断其他正在使用的任务。清理按确切 ID，发现仍在执行或审批的夹具先查明状态，不批量删除。

### 上线及回退

- P1 计算复用、P3 预读、P4 校准分别可关闭；P2 新参数是向后兼容扩展，旧读取模式始终可用。
- 回退只切换策略，不删除 task_results、Checkpoint、旧游标所指原文或审批记录。
- 部署前检查现有运行，采用已有受控重启与 Java→Agent RPC 就绪探测；没有通过就绪检查不宣称生效。
- 最终报告记录实际完成项、开关状态、测试范围、失败样本、性能取舍及未验证范围。构造中断与真实进程终止必须分别说明。

## 最终交付

1. 同轮派生计算复用及测量结果。
2. 多关键词/章节定位、后续命中游标和批量预算回收，兼容旧调用与恢复状态。
3. 经评测决定启用与否的明确来源预读。
4. 本地估算对供应商实际用量的校准指标与报告；证据充分时启用保守修正。
5. 离线、模型直调、Redis 跨进程、网站链路、长对话与审批恢复分别列明的验收记录。

本计划已执行。按计划在有证据的场景启用计算复用和本地明确来源预读；未启用自动降低 Token 安全余量。具体效果及限制以验收记录为准。
