# 写作侧栏工具

写作侧栏默认关联当前文章。每次发送问题时从编辑器取得新的 `editor_context`：文档标识、快照标识、标题、摘要、正文 HTML、完整性标识和选中文字。取消关联后不发送编辑器快照；手动附上的引用仍随该条问题发送，可单独移除。正文最多 32000 字符，选区最多 12000 字符；超出正文范围时不得生成全文替换，改用选区。

输入 `@` 或点击“@ 引用”，可选择当前草稿或选中文字，作为独立的引用标签附在本次问题上。点击标签展开原文，点击 × 移除，不把长文塞入输入框。引用固定为选择时的文字；编辑器关联快照仍在发送时读取。引用按选择顺序累加，每次最多 5 处、总共 12000 字；达到限制时保留已有内容并提示。标签独立编号、展开和移除，多个标签在可滚动区域内显示，避免挤掉输入框。选择、查看和移除均不发送请求。

写作页选中文字后的浮动工具栏最后提供“引用给 AI”：点击后保留选区、打开写作侧栏并追加引用标签，输入框保留已有要求并获得焦点，不自动发送。普通编辑和全屏共用同一入口；窄屏浮动工具栏可换行，确保末尾按钮仍可操作。无写作侧栏的其他编辑器不显示该按钮。

确认发送时，引用与问题通过既有用户消息字段传递，使用版本化 `easyjob-writing-reference` JSON 尾部封装；单处使用 v1，多个使用 v2 references 数组，历史兼容旧消息。整体遵守原有 16000 字符限制，超限保留输入并提示精简。用户消息即时展示和历史恢复均拆为问题气泡与折叠引用卡片，普通旧消息不变。会话冲突恢复时一起保留本次所有引用，正常发送后清空，避免下一轮重复携带。

服务端仍将引用作为用户提供的上下文，编辑应用继续使用本轮快照校验，引用本身不授予修改或保存权限。若用户在引用后切换选区，发送时清空不匹配的编辑快照选区，旧引用仅用于讨论。多处选区引用用于共同分析或对比，发送时不把最后一个选区当作整组引用的替换目标；选区修改建议仍需单独引用一处，以维持明确的位置绑定。

## 读取和提出修改

Main 使用 `retrieve.target=editor`，通过 `editor_part=document/selection` 读取本轮快照。读取结果不作为公共事实证据，不进入跨运行的公共结果复用。编辑器内容仅作为用户资料，不授予保存权限。

读取成功后，Main 可在 `answer.editor_edits` 提出一个标题、正文或选区替换建议。建议必须依赖本轮成功读取任务，并绑定同一个快照；正文替换必须已读取完整正文，选区替换必须已读取实际选区。后端核对绑定并核验替换内容，通过后才交付 `__EDITOR_EDITS__`。

建议显示原文、修改后内容及应用/忽略按钮。浏览器只在用户点击应用后修改编辑器，按目标进行冲突检查：标题仅比较标题；全文替换仅比较正文；选区通过 Slate RangeRef 跟随增删、节点拆分和合并更新位置，只检查原选区文字和富文本片段（包括格式和链接等属性）。其他段落、标题或摘要变化不会阻止选区应用。目标文字或格式变化、目标删除或定位失效时拒绝替换，不通过全局文字搜索改到另一处相同内容。文档切换、快照过期、登录账号变化和重复应用的校验仍保留。

本地最多保留 8 个快照，只保留有上限的请求上下文和选区定位数据；超过 32000 字符的完整 HTML、整篇纯文本不额外保留。选区富文本校验片段最多 128000 字符，超限时仅提供讨论，不能直接应用选区替换。快照淘汰、成功应用、文档切换或编辑器销毁时释放范围引用。撤销辅助记录最多 8 条，用正文变更计数和编辑器已有撤销批次验证，不再另外保存应用后的整篇 HTML。

正文修改形成单独撤销批次，标题也可通过卡片撤销。应用失败时回滚至点击应用前的当前正文，保留用户在等待期间对其他部分的修改。标题变化不影响正文修改的撤销；正文继续编辑后使用编辑器的常规撤销，避免误撤其他操作。应用后的保存沿用写作页原有自动保存和数据库版本校验机制。

建议保存在运行结果中，通过 SSE 回放和本人历史对话恢复。刷新后的浏览器缺少原始编辑快照，不能直接应用旧建议，需要重新生成。旧会话和旧 RPC 客户端可继续不传编辑器字段。

## 读取指定网页

Main 使用 `retrieve.target=knowledge`、`urls=[...]`、`allow_web=true` 读取指定公开网页，最多三个地址，不与平台文章筛选混用。地址必须来自用户输入或已取得的引用。服务端校验联网能力和公开 HTTP/HTTPS 地址，通过现有 DeepSeek Fetch 适配器读取，保留正文/节选标识，并进入原有引用和依据核验流程。失败时报告未读取成功，不自动用搜索结果替代指定页面。

## 验证

- `python-agent/tests/test_editor_tools.py`：真实状态图调度、快照绑定、权限、读取预算、内容核验失败、网页读取及回放。
- `frontend/tests-e2e/editor-tools.spec.ts`：重复文本选区定位、修改预览、确认应用、整体撤销、原文冲突和取消关联。
- `RpcInteropTests`：实际 Java Dubbo Triple 与 Python grpcio 双向互通，验证编辑快照字段传输；不连接业务数据库或模型。

真实模型、真实网页接口调用与部署环境验收需在启动后端服务后进行；上述回归使用冻结响应，不发送真实草稿。
