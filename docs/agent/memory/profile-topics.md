# 博客画像

对外 API 和 Main 上下文只使用 `topics`（关注领域）、`experience`（学习背景）和 `preferences`（回答偏好）。关注领域描述明确的长期阅读、学习、创作方向，不代表职业、熟练程度或代码语言。学习背景保留领域限定；普通问答与一次性写作需求不自动写入关注领域。

无需数据库 DDL：复用 `user_profile.interests` 存储统一关注领域，`tech_stack` 仅作为旧数据兼容列。读取时合并两列，去除空白与大小写重复；新写入同时清空 `tech_stack`，所以删除的领域不会重新出现。不截断已有条目，列表上限从原来每列20项调整为合并后40项，整体画像预算保持原有4000字。

旧检查点的画像在构造 Main 上下文、比较并发修改前也会统一转换。画像编辑版本基于合并后的内容计算，旧页面提交旧字段会被拒绝，应刷新后编辑；不会静默覆盖新画像。沿用原来的用户隔离、事务与并发冲突检测。模型新增领域需携带已有列表，仅用户明确删除或替换时移除。

验证：`test_structured_memory.py`、`test_memory_management.py`覆盖合并、保存、清空、防止旧标签复活、学习背景保留与并发版本冲突。`scripts/profile-topics-model-check.py`使用真实 Main 提示词检查明确关注、领域限定的新手背景、一次性问答以及追加关注领域，不写入数据库。
