# 关闭页面后会话被旧运行阻塞的修复

## 本次原因

会话 23776462841061376 的旧运行 8f82062e-8eca-4651-8c92-3d3c1ec02f29 于上海时间 23:02:36 创建。服务于 23:03 重启，内存执行器丢失，但数据库运行保持 running，直到原有 300 秒 deadline 才被置为 expired。页面重连依赖 sessionStorage 中的 runId，关闭标签页后无法通过会话定位旧运行。

旧阻塞记录现在已过期，该会话后续生成并保存的草稿未被清理。

## 修复

- 增加经过用户所有权校验的会话运行查询接口：Java `/api/agent/conversations/{conversationId}/run` 转发 Python `/conversations/{conversation_id}/run`。不返回执行 fencing token。
- 页面加载历史后直接查询服务端最新运行，running 时重放持久化 SSE；awaiting_approval 恢复草稿；已完成时补齐与历史读取竞态遗漏的结果；过期审批禁用旧按钮。
- 请求遇到 409 时核对并恢复既有运行，将被拒绝的文字和图片留在输入框，不把本地乐观消息当成后端接受的请求。
- 新增 nullable `agent_run.executor_lease_until`，正常执行每 10 秒续租，租约 45 秒。请求预处理、同步执行和后台流式执行均维持心跳；HTTP 订阅者不负责心跳。等待用户审批不依赖执行租约，继续使用审批 deadline。
- 续租须满足当前 token、running 状态、未过期租约及原有执行 deadline。过期租约不能被旧进程复活；已完成或等待审批的任务可继续发送终止帧。
- 查询运行、创建新运行及后台 10 秒扫描均会核验租约并回收失联运行。后台扫描意味着自动回收通常在 45 秒租约到期后的下一个 10 秒检查内完成；查询接口可以即时核验到期。
- 将并发名额的 ticket 与执行 token 绑定，失联、失败或取消时一起释放名额。清理只针对终止状态，不释放新的 running 代次。
- 模型/整体执行超时会输出明确中断提示并释放运行。旧版本留下的 NULL 租约运行保持原有 deadline 行为，避免误取消滚动部署中尚未使用心跳的执行器。
