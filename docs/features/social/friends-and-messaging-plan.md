# 朋友与私信扩展实施计划

日期：2026-10-22。状态：第一版代码与验收已完成；本机数据库迁移、服务重启及真实接口复核已通过。

按用户确认的“关注、粉丝、互关朋友”模式扩展本站。下列限额和交互是本站第一版的设计默认值，不声称与抖音当前规则完全一致。

## 1. 第一版交付范围

形成完整路径：发现作者 → 关注或回关 → 朋友列表 → 发起私信 → 分享文章。包含：

- 统一关系状态：关注、已关注、回关、互相关注。
- 消息页三个入口：消息、朋友、消息请求；朋友页提供搜索、备注和进入个人空间。
- 陌生人消息请求、接受、拒绝、拉黑，以及允许接收消息请求的设置。
- 备注、会话置顶、免打扰、移出消息列表。
- 聊天引用回复、文章卡片分享。
- 正确的未读状态、断线恢复、多端同步与手机布局。

朋友分组、聊天记录全文搜索、朋友动态、群聊、语音视频和多人文档协作列入后续版本，不作为第一版验收条件。

## 2. 产品规则

### 2.1 关系与朋友

| 我关注对方 | 对方关注我 | 展示 | 默认操作 |
| --- | --- | --- | --- |
| 否 | 否 | 关注 | 关注对方 |
| 是 | 否 | 已关注 | 再次点击弹出取消关注确认 |
| 否 | 是 | 回关 | 关注对方，成为朋友 |
| 是 | 是 | 互相关注 | 再次点击弹出取消关注确认 |

朋友由两条方向相反的关注记录推导，不另外保存一份容易不同步的好友名单。任一方取消关注，双方朋友列表及时更新；历史消息保留。备注只对设置者可见，取关后仍保留，方便识别历史会话。

按用户后续确认的交互，关注按钮不带下拉箭头；点击“已关注”或“互相关注”直接打开确认框，点击“确定”才取消关注，点击“取消”保留当前关系。私信使用页面上的消息入口。

个人空间、搜索结果、粉丝/关注列表、朋友列表使用同一个关系组件和状态定义。未登录用户显示登录入口；自己的页面不显示关注或私信自己的操作。

### 2.2 私信与消息请求

朋友关系和聊天许可分别管理：接受陌生人的消息请求不会自动关注对方；已经建立的正常聊天也不会因取关立即中断。拉黑优先于其他许可。

| 场景 | 发送能力 | 接收方入口 |
| --- | --- | --- |
| 当前互关，或已有获准的正常会话 | 文字、图片、文章卡片、引用回复 | 消息 |
| 尚未获准，且接收方允许消息请求 | 可发送一次不超过 300 个 Unicode 字符的文字招呼 | 消息请求 |
| 请求待处理 | 发起人可看自己已发送的内容，不能追加、发图或分享卡片 | 等待接受/拒绝 |
| 请求被拒绝 | 不能重新创建会话绕过限制；本版不提供重复申请入口 | 请求归档 |
| 接收方主动接受/回复，或双方后来互关 | 转为正常会话，保留原招呼 | 消息 |
| 任一方拉黑，或账号不可用 | 阻止新发送与新请求 | 原历史保留，输入区显示不可发送 |

请求在第一条招呼成功保存后产生；仅打开聊天页面不产生请求和通知。查看请求不等于接受。拒绝只关闭该请求，不删除已存内容。拒绝后，接收方主动发起聊天或双方互关可重新开放聊天；创建/删除会话、撤回招呼、重试接口均不能恢复招呼额度。

接收消息请求开关只影响新的陌生请求，已有正常聊天继续可用。关闭后不接受新请求，已有待处理项仍可查看、接受或拒绝。新请求默认每个账号滚动 24 小时最多联系 20 个不同陌生人，参数集中配置；同一目标的并发请求与重试只计一次。该数值是初版默认值，可后续按使用情况调整。

拉黑时清除双方关注关系、更新计数，屏蔽双方新私信与在线状态可见性；解除拉黑不自动恢复关注或已拒绝的请求。界面在拉黑操作前明确说明这些结果。对被拉黑者使用统一的“暂时无法向该用户发送消息”提示，不公开对方的私人设置。

### 2.3 会话管理和未读

- 置顶、免打扰、移出列表仅影响当前用户。置顶会话按最后消息时间排序。
- 免打扰仍保存消息、投递实时事件、更新会话内未读；不弹提醒，不计入全局普通消息提醒数。接收人查询不能过滤免打扰用户。
- 移出列表不删除历史和聊天许可；后续允许的来信可以重新显示会话。
- 普通消息未读和待处理请求数分开展示，页面导航、消息列表和多端采用同一后端口径。
- 普通消息只在会话可见、窗口有焦点、内容实际展示到对应位置后提交已读游标。读到旧消息不能清掉同时到达的新消息。未读游标只前进，不回退。
- 请求列表区分“未查看”和“待处理”；打开请求只消除未查看提醒，不自动接受。接受/拒绝后待处理数减少。

### 2.4 引用与文章分享

- 引用回复展示来源发送人和短摘要，点击可加载并定位同会话原消息；撤回的原消息显示“原消息已撤回”。服务端验证引用属于当前会话，不接受客户端提供的任意原文。
- 从文章详情页的“分享”按钮打开分享面板：展示当前文章预览、朋友头像列表及昵称/备注搜索，选择朋友后确认发送文章卡片。一次向一个目标发送；复制链接作为面板内的其他选项。聊天输入区不再提供分享入口，也不需要填写文章链接或 ID。
- 新增文章卡片消息类型，发送参数使用文章 ID。服务端解析标题、封面、作者和访问状态；不信任前端伪造的卡片内容。
- 首版只分享当前公开且可访问的文章，不包含草稿、审核中内容或私有资料。文章下架/删除后，消息位置保留并显示“文章已不可用”，不继续展示被撤下的封面和标题，也不允许绕过文章权限打开内容。

## 3. 页面安排

桌面延续现有消息页的左右布局。左侧顶部为“消息 / 朋友 / 消息请求”，下方搜索与对应列表；右侧为聊天或联系人详情。朋友行显示头像、备注优先的名称、昵称及发消息操作。消息请求右侧展示招呼和接受/拒绝/拉黑操作，接受后平滑进入同一条正常会话。

粉丝与关注页面增加“朋友”标签，粉丝行可直接回关。个人空间显示统一关系按钮。手机采用列表与详情两级页面，返回时保留原列表位置和搜索条件。

会话头部菜单承载备注、置顶、免打扰、移出列表和拉黑。加载、空列表、请求待处理、账号不可用和发送失败均有明确状态；发送失败可重试但不能重复入库。关系或请求状态从其他设备改变时，当前页面同步更新发送能力。

## 4. 对照现有代码的技术方案

### 4.1 可以复用的基础

- `user_focus`：已有关注与粉丝关系；补唯一约束/查询索引并统一幂等写入及计数维护。
- `conversation`、`conversation_member`、`message`：复用单聊、消息历史、分页和撤回。
- `conversation_member.is_top`、`is_muted`：字段和查询已有，补写接口、完整交互与提醒口径。
- `MessageServiceImpl`：已有 `clientMessageId` 幂等、会话锁、事务提交后 WebSocket 推送及 `replyToMessageId` 校验，可在此扩展。
- `Chat.vue`：已有文字、图片、虚拟消息列表、断线后按游标补消息和在线状态；拆出列表、联系人、请求和消息卡片组件，复用统一会话状态。

### 4.2 必须先解决的现有缺口

1. `ConversationServiceImpl.createOrGetConversation` 目前按目标用户建立会话；`MessageServiceImpl.sendMessage` 主要检查成员资格。补统一聊天策略服务，创建会话不能替代每次发送时的权限判断。
2. `ConversationMemberMapper.selectOneReceiveId` 排除了免打扰和移出列表的接收方。接收人身份、历史访问、列表显示、提醒偏好分开处理，避免漏实时消息或错误关闭已有聊天。
3. `Chat.vue` 总未读直接累加全部会话，而后端总未读排除免打扰，需统一口径。
4. 当前清空未读的实现没有携带客户端实际读到的消息游标，需避免“读旧页同时收到新消息”被一起清零。
5. `ChatWebSocketHandler` 当前发送全站在线用户集合，并向所有在线连接广播状态。调整为当前用户有权查看的朋友/正常会话对象；拉黑、取关、请求变化及时更新订阅范围，撤销访问后移除客户端旧状态。
6. 同一对用户并发创建单聊、发送首条请求和反复关注的唯一性需要在数据库层保证，不能只依赖先查再插。

### 4.3 数据设计

下列名称为实施建议，落地时与现有迁移规范统一：

| 数据 | 存储方式 | 关键约束 |
| --- | --- | --- |
| 关注 | 现有 `user_focus` | `(user_id, focus_user_id)` 唯一；反向查询索引；禁止自己关注自己 |
| 朋友 | 双向关注查询推导 | 无独立好友状态表；查询同时应用账号与拉黑规则 |
| 私人备注 | 新增 `user_contact_setting` | `(owner_id, target_id)` 唯一；仅本人读写；备注最多 50 个 Unicode 字符 |
| 拉黑 | 新增 `user_block` | `(user_id, blocked_user_id)` 唯一；双向阻断查询索引 |
| 消息请求设置 | 用户隐私设置字段/表 | `allow_message_requests`；仅本人可修改 |
| 单聊映射与许可 | 新增 `direct_chat_state` | 有序用户对 `(user_low_id, user_high_id)` 唯一；关联唯一会话；记录状态、发起人、处理时间、请求查看时间 |
| 请求状态 | `NONE / PENDING / ACCEPTED / DECLINED` | `NONE` 只是尚未提交请求；按用户对持久化，删除会话不重置 |
| 会话偏好和已读 | 复用 `conversation_member` | 偏好按成员保存；读游标单调递增；展示隐藏不等于撤销成员身份 |
| 文章消息 | 扩展 `message` 的卡片字段和类型 | `messageType=3`；服务端校验文章；旧文本和图片格式继续可读 |

正常聊天的许可来源记录为互关建立、显式接受、接收方主动回复或旧会话兼容，以便排查“为什么允许聊天”。已有许可不会被前端传入的状态覆盖。

### 4.4 服务与接口边界

新增关系查询/写入服务和统一聊天策略服务。身份始终取服务端登录上下文；后端根据关注、拉黑、请求许可、隐私设置、账号状态及请求额度判断 `canMessage`。前端接收关系展示、可执行操作和不能发送的原因，只负责展示。

计划新增/扩展接口：

- 朋友列表和关系查询：分页、昵称/备注搜索；关系字段批量返回，避免逐个查询。
- 幂等关注/取关、备注、拉黑/解除拉黑、消息请求隐私设置。
- 消息请求列表/详情、查看、接受、拒绝；只能由指定接收方处理。
- 当前成员的置顶/免打扰偏好，以及带 `lastReadMessageId` 的已读提交。
- 发送接口扩展文章卡片；原有文字、图片、引用回复统一走发送策略。

所有影响双向关系或发信许可的写入使用一致锁顺序：先锁有序用户对，再处理其会话和消息。首条招呼、接受/拒绝、拉黑和消息发送放在事务内校验，避免并发绕过限制。通知和 WebSocket 事件在提交后投递；重复请求返回同一结果，不重复消息、关注计数或提醒。跨用户额度用后端原子计数/限流机制，参数和失败返回集中管理。

WebSocket 增加关系/请求/偏好变化通知，事件携带版本或更新时间；客户端按消息 ID 和幂等键去重，状态不明确时重新拉取权威快照。重连后分别补消息、关系/请求状态和未读汇总，WebSocket 不是唯一状态来源。

## 5. 实施顺序与每步验收

| 步骤 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 1. 关系基础 | 迁移、关系服务、统一按钮、朋友列表、回关、备注、拉黑 | 双向关注成为朋友，取关/拉黑立即更新，重复/并发操作不造成计数漂移；不同用户备注互不影响 |
| 2. 私信准入 | 单聊唯一映射、请求状态、隐私设置、发送策略、请求页面 | 陌生人只成功发一条文字；并发、重试、撤回、删除会话不能绕过；接受或互关后恢复正常聊天 |
| 3. 会话体验 | 置顶、免打扰、移出列表、已读游标、提醒统计、实时同步 | 静音仍实时收消息；读旧消息不吞新未读；多端操作一致；断线重连恢复；手机导航正常 |
| 4. 内容交流 | 引用回复、文章卡片、分享给朋友 | 可定位原消息；撤回引用有降级；公开文章可分享；下架和私有文章不能借卡片泄露；分享重试不重复 |
| 5. 整体验收与接入 | 迁移演练、关键回归、视觉检查、生产构建 | 老聊天可用、文章/编辑器不受影响、接口和 UI 规则一致、构建通过，清理本轮测试日志与报告 |

按顺序完成，不在后端准入规则未落地时提前开放陌生人消息入口。

## 6. 旧数据和接入

- 新迁移沿用仓库已有的 `python-agent/migrations/` 编号机制，实施时取下一个空闲编号；同步 `deploy/mysql/schema.sql` 与集成测试 schema。
- 迁移前检查重复关注、重复单聊及计数差异。存在重复单聊时先给出不丢消息的归并与旧 ID 兼容方案，不直接依赖建唯一索引失败后重试；历史记录不静默删除。
- 已有实际消息的旧会话记为正常会话，保留原交流能力；仅创建但没有消息的空会话不自动获得准入。此兼容规则意味着新请求规则主要约束此前没有聊天历史的用户对。
- 迁移和初始化可重跑，记录完成状态，避免再次回填时给新会话错误授予旧会话许可。
- 部署采用先增加数据结构和兼容后端，再接入新页面的顺序；通过功能开关逐步开放新入口。回退首先关闭入口并恢复兼容页面，保留新增关系与请求数据，不能通过回退页面绕过后端发送限制。
- 开发验证使用隔离端口、模拟文章/用户或测试数据库；不修改用户真实关注、私信、文章，不自动执行真实数据迁移或重启运行中的服务。

## 7. 重点测试

业务与并发测试覆盖：四种关系状态、互关与取关、拉黑/解除、隐私开关、拒绝后再次发起、双向同时发起、首条招呼重试与并发发送、接受/拉黑与发送同时发生、重复关注计数、单聊唯一性、越权查看/接受/改备注/改会话偏好。

消息测试覆盖：免打扰正常投递、请求与普通消息分流、已读游标并发、同账号多标签页和多设备、断线恢复、旧消息兼容、图片/撤回/引用原功能、文章删除/下架后的卡片访问。

浏览器验收使用至少三个隔离账号状态：A 与 B 互关，C 与 A 陌生。验证所有页面按钮一致，搜索与备注生效，请求只出现一次，接受后原请求进入同一会话，取关和拉黑即时改变能力，桌面/手机布局与键盘操作正常。

每步运行对应测试；最终运行完整受影响的关注、私信、通知和文章分享回归及前端/后端构建。结果记录在本计划后续实施记录中，测试产生的临时报告验证后清理。

## 8. 实施记录（2026-10-22）

第一版五个步骤均已落地：

- `SocialService` / `SocialPolicy` 统一关系事实、聊天许可和发送准入；旧关注和私信入口委托同一服务，不允许前端自己授予聊天权限。
- `FollowButton` 在个人空间、搜索、粉丝/关注列表与聊天页统一关注、回关和互关状态。消息页新增朋友、消息请求、备注、黑名单和隐私设置。
- 单聊使用有序用户对唯一映射；发送、处理请求、拉黑、已读使用一致锁顺序。首次请求额度按不可转移的 `requested_by` 与 `requested_at` 统计，拉黑、解除拉黑、撤回和隐藏不能重置额度。
- 导航与聊天共用一个引用计数 WebSocket，重连补拉权威状态。普通未读与请求未查看分开统计；免打扰不漏投递；已读带实际展示游标。在线状态限于有权查看的联系人。
- 仅打开空会话不会把空聊天推入接收方列表；拒绝请求后不转成普通未读提醒，接收方以后主动回复时才恢复正常会话。已有获准聊天被拉黑后仍保留历史入口。
- 引用回复可加载较早原消息并返回最新，撤回及时降级。从文章页“分享”面板向朋友发送公开文章，聊天中展示卡片；卡片信息由服务端生成，失败重试保留幂等键。
- 迁移保留重复单聊的消息 ID，旧会话 ID 解析至规范会话；原关注行另存备份，回填只执行一次，脚本和 SQL 校验和发生变化时拒绝重复执行。

## 9. 接入运行环境

```powershell
python scripts/migrate-social.py
```

只执行 SQL 文件不足以升级旧库，必须使用该脚本完成历史归并、计数重算、索引和版本标记。发现非双人旧单聊、旧类型 3 消息或校验和不一致时，脚本会停止并提示核对，不能通过删除版本标记强行绕过。

```yaml
easyjob:
  social:
    enabled: true
    daily-request-limit: 20
```

默认已启用。`enabled: false` 会隐藏朋友/消息请求列表并阻止新的陌生人招呼，但保留关注、历史记录、现有获准聊天和互关聊天；它不撤销已授予的聊天许可，也不是旧数据库兼容开关。修改配置后需重启后端生效。已存在的待处理请求数据继续保留。
