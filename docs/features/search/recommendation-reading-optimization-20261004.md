# 推荐、有效阅读与运行稳定性改进

日期：2026-10-04。迁移 008 已应用到本地 MySQL，Java、Python Agent 和前端服务已使用本轮代码。

## 用户可见变化

- 推荐综合近 30 天标签兴趣、互动量和发布时间计算，近 7 天读过的文章降权但仍可展示。兴趣直接查询近期行为，用户无需等待每日任务刷新。
- 新文章具有新鲜度加分；阅读、点赞、收藏、评论使用对数权重，避免历史总量长期垄断排序。支持分类、标签过滤及分页，排序以发布时间和文章 ID 消除同分不确定性。
- 首页展示推荐理由，并防止切换分类或排序时旧请求覆盖新结果。
- 文章成功加载后累计前台可见时间，达到 15 秒上报；后台标签页暂停累计，离开页面释放计时器，详情请求本身不增加阅读量。
- 登录账号按账号身份、游客按 HttpOnly 浏览器 Cookie 去重。同一读者对同一篇文章每个上海自然日计一次；作者查看自己的文章不计数。SQL 事务内同时保存阅读凭据、原子递增计数和登录用户阅读历史。
- 已有阅读总量保留，新规则不追溯重算。游客清理 Cookie 或由游客转为登录身份会形成不同身份；15 秒是前端有效阅读规则，不等同于服务端反作弊证明。

推荐权重为：标签匹配每项 3 分；阅读/点赞/收藏/评论的对数权重分别为 0.7/2/3/1.5，互动随文章年龄衰减；新鲜度为 2/(1+小时数/24)，近期已读整体乘以 0.35。它是可解释规则，没有宣称已经提高线上点击率或推荐准确率。

## 同步落地的稳定性改进

- 知识检索任务携带明确筛选范围。改写故障时保留 Main 指定范围；没有可信范围时停止检索。明确作者、分类或指定标签不能解析时，不扩大为全站搜索；回查 SQL 继续核验筛选条件及内容版本。平台身份/时间等限定条件不由无法验证这些条件的网页检索替代。
- 审批异常后查询实际运行状态，恢复最新审批预览、已保存链接或正在运行的事件流；过期和取消后关闭旧审批按钮。
- 文章 embedding 按模型、维度、完整文本 SHA-256 缓存 7 天；批内同文去重，只计算缓存缺失项。更新仍写入当前索引元数据，缓存不会跳过权限或版本更新。
- Python 联网、精排、向量读取每供应商并发上限 4，最多 2 次只读尝试，总时限分别 16/18/20 秒；连续 3 个失败调用熔断 30 秒，恢复时单探针。鉴权错误不重试。熔断是进程内机制；Java 侧所有外部调用尚未统一使用这一策略。
- 增加运行过期/近期统计、公共文章列表、用户行为查询索引；阅读凭据分批清理，保留累计阅读量和用户历史。
