# 阅读与回答反馈

文章页提供页面内加载重试、窄屏目录、字号与宽度设置。目录标题完整换行；窄屏点击“目录”打开列表，选择章节后关闭列表并避开固定导航和阅读工具栏。

“分享本节”复制带章节锚点的链接。锚点由标题文字和同名标题出现次数生成，插入其他标题不会改变原章节链接；旧 `heading-N` 链接仍可定位。章节重命名或删除后，旧链接可能失效。

阅读位置按账号、文章在当前浏览器保存，最多保留最近 50 篇，记录章节与章节内相对位置。重新打开时由用户选择“继续阅读”；显式章节链接优先。文章正文发生变化或当前无全文阅读权限时，不使用旧位置。此功能不同步设备，也不修改有效阅读计时规则。

文章和 AI 回答共用代码工具：放大查看、字号、换行和复制；AI 还可以复制原始 Markdown 回答。代码查看器不执行代码。

## 反馈处理

数据库变更为 `python-agent/migrations/024_feedback_review.sql`。升级已有环境执行：

```powershell
.\python-agent\.venv\Scripts\python.exe scripts/migrate-product-features.py
```

迁移可重放，保留原有反馈。容器首次启动及 `python -m app.migrate` 也会应用本迁移。

后台入口为“Agent 指标 → 回答反馈”。权限分开校验：

| 权限 | 功能 |
| --- | --- |
| `metrics.read` | 分类统计、反馈运行编号和处理状态 |
| `feedback.read` | 用户补充说明、对应问答、最近 100 条执行状态和最近 20 条处理记录 |
| `feedback.manage` | 待处理／已解决、处理说明与历史记录 |

管理员拥有以上权限；仅有指标权限的运营角色不会自动获得查看私人问答的权限。原始问题通过运行记录中的 `user_message_id` 精确定位，实际回答通过 `run_id` 定位，不读取整段会话。旧运行缺少关联时显示缺失原因，不猜测原问题。已删除会话不再展示问答内容。查看详情写入 `agent_admin_audit`，处理写入 `agent_feedback_review_log`。

标记“已解决”必须填写说明。保存同时检查处理版本和反馈提交标识；同一请求重试幂等。用户更新、撤回再提交反馈时，旧表单不能覆盖新反馈，状态回到待处理，历史处理记录保留。反馈本身不会自动重新生成答案或训练模型。

验证：浏览器回归位于 `frontend/tests-e2e/reading-feedback-workflows.spec.ts`，真实 MySQL 生命周期验收为 `python scripts/feedback-review-smoke.py`（临时数据结束后清理，不调用模型）。
