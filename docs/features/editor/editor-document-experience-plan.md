日期：2026-10-21。用户要求由主代理制定方案，GPT-6.1-Sol 执行。

## 目标和现状

将文章编辑从固定高度的表单改成连续写作的文档体验，沿用项目的纸色、墨色和荧光绿。此轮参考云文档常见交互，不宣称实现飞书全部能力或多人协同。

已确认：阅读页与编辑器共享标题装饰 CSS，一级标题及空标题产生横线和过大留白；正文固定 560px 内滚动；完整工具栏折成两行；摘要和发布信息常驻；保存中继续编辑时成功提示可能先于实际最新内容保存。

## 执行顺序

1. **写作画布**：新增明确的 document 布局模式用于 CreateArticle/EditArticle。普通模式正文随内容增长，页面负责滚动；工具栏在页面操作栏下吸顶，不能遮住光标或标题。AI 草稿弹窗保留受限高度，全屏保留单一正文滚动区。编辑器标题使用紧凑无装饰的层级，阅读页标题不变，不删除用户已有空段或真正的分隔线。
2. **文档头和发布信息**：标题 Enter（排除输入法组合态）跳入正文，不触发提交；摘要默认收起，可清楚展开和编辑。封面/分类/标签等发布设置改为按需打开的区域，错误校验自动展开并定位；新建和编辑页面一致。保持已有版本锁、审核、AI 关联和路由语义。
3. **工具与块操作**：主工具栏仅常用格式、列表、插入、撤销/重做、全屏；将字号/行高及低频插入放入更多/插入菜单，不让窄屏工具栏挤占两行大片空间。保留选区工具条及引用给 AI。空普通段落输入 `/` 打开可搜索命令菜单，提供正文、H1/H2/H3、无序/有序/待办列表、引用、代码块、分隔线；上下选择、Enter 执行、Escape 关闭，鼠标操作保留原位置。中间斜杠、链接、代码块和输入法组合时不误触发；只移除本次命令字符，保留其余文档和撤销栈。菜单定位限于可见视口，能在全屏/移动端正常用。
4. **键盘与保存**：核查并补齐标题末尾 Enter 转正文、空标题 Enter 转正文、空列表 Enter 退出、Shift+Enter 软换行；保留正常段中拆分和代码行为，避免全局键盘劫持。Ctrl/Cmd+S 手动保存且不打开浏览器保存网页。区分待保存、保存中、已保存到服务端、本机暂存、失败/冲突；请求途中新修改不得显示为全部已保存。保持现有标题和分类服务端约束，缺失时给可点击补齐入口，绝不能将本机暂存标成云端已保存。

## 复制缩进与悬停段落格式

按用户要求补齐复制与悬停操作。Tab 的缩进仍是段落的 `text-indent`，不向正文插入空格，也不恢复已取消的标题自动缩进。

- 复制/剪切前同步实际 DOM 选区，避免刚选中文字立即复制时使用旧选区。保留原生 Slate 富文本片段；单段复制补回包含缩进的段落或标题容器。纯文本复制在所选段落开头用制表符表示手动缩进，段中截取不额外添加前缀。
- 只在剪贴板副本中移除编辑器的结构包装并规范化行内样式，避免 HTML 粘贴丢失字号；复制本身不修改正文或撤销记录。粘贴到空段时恢复复制段落的类型、缩进、对齐与行高；粘贴到已有正文中保留目标段落的格式。图片继续复制已有图片引用。
- 鼠标悬停可编辑的段落、标题、列表或引用块时，在左侧固定预留的空隙显示类型按钮。点击可以切换正文和 H1–H5，使用与工具栏相同的转换函数。仅修改悬停块，保留行内样式、链接和手动缩进；不转换表格、代码块和图片等结构。
- 悬停块使用 Slate PathRef 跟踪，随编辑、滚动和宽度变化更新位置；失效时关闭。菜单限制在可视区域，支持键盘方向键、Enter 和 Escape，在普通页面、全屏和 AI 草稿弹窗中复用。菜单内 Escape 先关闭菜单，再次 Escape 可以退出全屏。

## 飞书现场实测：首行缩进与块层级（2026-10-21）

用户进一步澄清：在目标空行先按一次或两次 Tab，再粘贴包含标题和多段正文的内容。此前“把来源段落缩进恢复到空行”的实现不能满足这个行为。用户授权登录后，已通过浏览器 UI 新建《编辑器缩进与粘贴测试（临时）》并完成实际键盘操作；没有改动已有文档。

测试文档：https://my.feishu.cn/wiki/Kkn5wBpYUiMYuFk97AEcAJaknpr

已验证的行为（这些结论来自实际 UI、可见 DOM 与正常复制取得的剪贴板，不是内部源码分析）：

1. 普通空正文行行首第一次 Tab，只启用首行缩进。目标仍位于原父块，测得 `text-indent: 32px`，整块左边界不变；复制数据中有单独的 `text_indent: 1`。
2. 第二次 Tab，将该块挂到前面的正文块下面，形成一层结构嵌套；原首行缩进仍保留。DOM 出现嵌套的 `text-children` 容器。在本次页面中子块每层左移约 25 CSS px，此数值仅为现场观察，不作为项目固定布局规格。
3. 在该块没有可继续承接缩进的前置同级块时，再按 Tab 出现“当前内容块已达最大缩进层级”，并保持现有位置。
4. Shift+Tab 优先取消首行缩进，再按才退出一层结构嵌套，已分别验证。
5. 将“一级标题＋三段未缩进正文”复制到只按一次 Tab 的空行后，复制后的标题和正文均回到原来对齐位置，首行缩进为零，仍在根层。粘贴会使用复制内容自己的首行格式，不能把目标空行的首行缩进当成整组内容的结构缩进。
6. 从无缩进空行重新按两次 Tab 后粘贴同一组内容，四个新块都成为目标原父块的子块，整个组保留一层结构缩进；复制内容的首行格式仍为零。这完整复现用户截图的整体右移。
7. 在已缩进的标题末尾 Enter，新正文与该标题同一父块、同一左边界，首行缩进为零；不会因为标题级别再自动添加缩进。
8. 并非所有正文最多只能按两次 Tab。把前一正文先挂在标题下，再缩进后一正文，可以继续形成更深的“正文 → 标题 → 正文 → 正文”父子链，随后触顶。上限与当前位置是否有合法的父块/前置内容相关，不能直接写成“所属标题缩进＋2”或全局只能两个 Tab。

正常富文本复制提供 `docx/record`、`text/html`、`text/plain`；记录中的 `type`、`parent_id`、`children` 与单独的 `text_indent` 区分了内容类型、结构关系和首行格式。没有读取应用 JS store、接口或凭据。

后续改造应拆开“首行格式”和“块层级”两种状态，并在粘贴时保留来源内部结构、挂接到目标父级。不能继续用同一个 `text-indent` 数值同时代表两者，也不能只给绝对像素值做平移。本轮仅完成飞书行为实测，生产代码未调整上述逻辑。

## 首行格式与块层级实现（2026-10-21）
