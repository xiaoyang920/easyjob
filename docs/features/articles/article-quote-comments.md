# 文章划词评论

正文选中最多1000个 UTF-16 单位的文字后，点击“评论所选内容”，在右侧填写最多500字的评论。阅读工具栏的“划词评论”可打开已有讨论。手机端使用抽屉；未登录可以查看有阅读权限文章的讨论，发布时会提示登录。一般评论区也保留引用卡片和定位入口。

已有评论的正文片段显示常驻黄色提示线，点击或轻触会打开“这一处的评论”；同一位置的多条讨论合并显示，重叠片段显示命中的全部讨论。可切回全部评论。提示线不拦截正文选择、复制或原有链接/代码按钮；关闭侧栏后仍保留。字号、宽屏、代码/表格内部滚动时重新计算位置及裁剪，不修改正文 DOM。

`GET /api/comment/quote-markers` 按评论ID游标分页读取轻量引用数据（每批最多200条），不依赖侧栏首屏评论。`GET /api/comment/quotes?ids=...` 按文章及指定评论ID读取讨论（每次最多50个ID），前端对命中评论继续分页；两个入口均检查当前文章阅读权限，无法通过评论ID读取其他文章的讨论。

划词评论复用原评论及回复接口、身份、通知和删除流程。新增 `GET /api/comment/quotes` 分页读取有引用的顶级评论。创建评论的 `quote` 包含原文 `exact`、48单位的 `prefix/suffix`、正规化正文的 `start/end` 位置；服务端基于当前已发布正文验证，计算正文哈希，并与评论在同一事务中保存。文章作者以数据库为准。回复属于原线程，不另建正文引用。

正文正规化在 Java 和浏览器保持一致：段落、标题、列表、表格、代码等块之间插入空格，合并空白；忽略脚本、样式和代码工具栏。文内高亮使用 CSS Custom Highlight，兼容路径使用不拦截点击的覆盖层，不修改富文本、代码高亮及目录 DOM。

点击引用先检查原位置和前后文；文章内容移动时用前后文重新寻找。找不到原文或重复内容存在歧义时保留原始引用，提示“原文已修改或位置无法确认”，不会指向其他段落。本文能力面向文章阅读讨论，尚不包含多人编辑、评论解决状态和飞书完整协作工作流。

数据库增量迁移：`python-agent/migrations/025_article_comment_anchors.sql`，通过现有 `python -m app.migrate` 或 `scripts/migrate-product-features.py` 执行。新增引用表，旧评论不需回填；外键保证删除评论时一并删除引用。所有新业务 SQL 位于 Mapper XML。

验证：前端定位单测覆盖跨段、内联标签、代码、重复句、文本移动及 Emoji；浏览器覆盖发布、刷新、回复、删除、冲突保留输入、原文失效、手机和登录。Java 单测验证引用、权限和原子创建边界。`scripts/comment-anchors-http-smoke.py` 使用临时账号和文章测试真实网关/Java/MySQL 链路，并清理临时数据。
