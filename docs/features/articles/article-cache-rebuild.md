# 文章详情缓存重建互斥

文章详情仍采用固定 Key 的旁路缓存，保留原有发布和修改后的失效逻辑。

命中 `easyjob:articleDetail:{articleId}` 时直接返回缓存，不获取锁。未命中时，通过 Redis `SET NX PX` 获取该文章的重建锁；获取成功后再次检查缓存，仍未命中才查询正文和作者信息并回填。不同文章使用不同锁，多实例共享 Redis 时也共享重建锁。

未获锁的请求每隔最多 50ms 检查缓存并尝试获取锁。默认最多等待 2 秒，超时返回业务错误码 503 和“文章正在加载，请稍后重试”，不让所有等待请求同时查询数据库。等待期间被中断则立即退出等待。

锁默认租约为 30 秒，避免进程异常退出后锁永久保留。释放采用 Lua 原子比较持有者令牌再删除，旧持有者不能删除后来请求取得的锁；已发现租约失效的请求不回填缓存。数据库加载失败也在 finally 中释放锁。释放失败由租约兜底，不覆盖原始查询异常。

配置位于 `easyjob.cache.rebuild-lock-lease-ms` 和 `easyjob.cache.rebuild-wait-ms`。租约必须覆盖正常正文查询和回填耗时；数据库调用超过租约时，新的请求可能接手重建。此锁用于抑制缓存击穿，不是数据库与缓存的一致性协议。

动态计数、文章状态、访问权限和当前用户的点赞收藏状态仍在缓存正文之外查询或校验，不写入共享缓存的个人状态。

验证：`CacheRebuildMutexTests` 覆盖两个组件实例下 24 个并发请求仅加载一次、不同文章不互相阻塞、二次检查、等待超时不回源、异常释放、旧持有者安全释放及中断退出；`ArticleLifecycleTests` 验证命中缓存后仍查询实时计数和校验文章可见性。
