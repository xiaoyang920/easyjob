# 文章版本审核

## 数据结构

本次复用现有 Vue 与 Spring Boot 服务。`article_info` 保持文章身份和当前公开版本，评论、点赞、收藏与阅读量继续关联同一文章 ID。其可见状态仍然为 0 未公开、1 已发布、2 已下架，不将审核状态混入可见状态。

新增 `article_revision` 保存完整内容快照，包括标题、摘要、正文、封面、分类、标签、原创标识。正文快照一经创建不修改，只允许审核状态迁移。版本状态为 0 草稿、1 待审核、2 已通过、3 已驳回、4 已撤回、5 已替换。版本号由后端在文章行锁内分配；待审核版本有数据库唯一约束，确保同一文章至多一个待审核版本。

`article_info.latest_revision_id` 指向作者当前版本，`published_revision_id` 指向当前公开版本。提交版记录 `base_revision_id` 和规范化 JSON 的 SHA-256；管理员通过时同时验证当前头版本、原公开版本和正文校验值。

新增 `article_review_log` 保存提交、撤回、通过、驳回、丢弃修改的操作人、版本 ID、内容校验值、意见和时间。快照和审核记录保留在本地数据库中，历史界面展示最近 100 个版本。

## 作者流程

首次创建或 AI 保存的文章属于未公开内容。保存版本草稿不会公开；点击“提交审核”后，进入待审核队列，通过前不出现在首页、搜索、推荐或公开详情中，也不增加已发布文章数。

已发布文章修改时，编辑器读取作者最新版本。保存、提交、驳回或撤回都不会覆盖旧公开版。审核通过后才将该版本写入公开内容，保留原发布时间、文章 ID 和互动数据。

编辑器携带 `expectedRevisionId`；过期编辑返回 409，避免两个浏览器页面覆盖彼此的修改。待审版本被锁定，作者需撤回后才能继续编辑。驳回后可以修改再提交，也可以再次提交同一内容，但提交始终创建独立的新审核版本，旧驳回记录不会被覆盖。

草稿箱升级为“草稿与审核”，提供草稿、待审核、已驳回、已撤回筛选、驳回原因、撤回和版本历史。历史内容恢复会创建新草稿，需要重新审核才能对外生效。已发布文章的“丢弃修改”只恢复编辑头指针，不删除公开文章或历史快照。

历史已发布文章不会因升级被隐藏或重新审核。首次修改时，在同一事务中将现有公开内容补成已通过的基准快照。未生成过版本的 AI 草稿仍然可以打开编辑器，再提交审核。

## 管理员流程

管理后台新增“文章审核”，可以查看待审、通过、驳回和撤回记录。详情并排展示提交时的公开基准版与完整提交版，并提供封面、分类、标签及审核轨迹。历史审核记录始终对照原基准快照，不会随之后的公开内容变化而改变。驳回意见必填，最多 1000 字；提交审核结论需再次确认。

接口始终从数据库验证管理员角色和正常账号状态。普通用户不能访问审核详情，作者只可查看自己的私有版本。操作按“文章主键 → 版本主键”的顺序加行锁，版本状态使用 `FOR UPDATE` 当前读，避免 MySQL REPEATABLE READ 快照读到过期的待审状态。同一审核版本只能处理一次；审核与撤回竞争时只允许一个成功，另一个返回 409。下架文章不能通过作者提交恢复公开。

通过时，公开正文、版本指针、作者首次发布计数、标签关联、索引 outbox 以及审核日志在一个事务提交；提交后清理文章和个人空间缓存。正文只在通过审核时进入搜索和向量索引更新链路。

## 审核结果通知

管理员通过或驳回待审核版本时，向作者写入现有 `notification` 表，类型为 6（通过）或 7（驳回）。文章 ID 关联文章，target_id 关联这次审核的不可变版本；标题、版本号与审核意见预览取自这次审核，后续编辑不会改变旧通知。通知意见预览最多 200 个字符，完整意见保存在原审核版本（最多 1000 字）。

通知与公开投影、版本状态及审核日志处于同一 Spring 事务；通知写入失败时审核回滚，审核回滚时不推送。事务提交后沿用 RabbitMQ → SSE 推送，在线推送失败不改变已提交审核结果，作者仍可通过通知列表读取；连接恢复时刷新未读数。审核自己的文章也会收到结果通知。重复或过期审核、撤回竞争失败、权限拒绝与内容校验错误不会产生结果通知。

通知页新增“审核”分类，后端按类型/未读过滤后分页。通过通知打开公开文章；驳回通知打开草稿与审核中的对应历史版本及完整意见，作者可基于该版本创建修改草稿。查看旧驳回通知不会覆盖或回退当前版本。

## 接口列表

- 创建和修改沿用 `/api/article/create`、`/api/article/{id}`：DTO 的 `status=0` 表示保存版本草稿，`status=1` 表示提交审核，不再表示立即发布。
- `POST /api/article/{id}/publish`：携带 `expectedRevisionId`，提交当前版本审核。
- `GET /api/article/{id}/edit`：读取作者最新版本，同时返回公开状态、版本 ID、审核状态和审核意见。
- `GET /api/article/work`：作者创作版本列表；`state` 可筛选 0、1、3、4。
- `GET /api/article/{id}/revisions`、`GET /api/article/{id}/revisions/{revisionId}`：作者历史版本和完整内容。
- `POST /api/article/{id}/revisions/{revisionId}/withdraw`：撤回待审版本。
- `POST /api/article/{id}/revisions/{revisionId}/discard`：丢弃未提交的修改版本，保留公开版本。
- `POST /api/article/{id}/revisions/{revisionId}/restore`：携带 `expectedRevisionId`，基于历史内容创建新草稿。
- `GET /api/admin/reviews`、`GET /api/admin/reviews/{revisionId}`：审核队列和对照详情。
- `POST /api/admin/reviews/{revisionId}`：`decision=approve/reject`、`reason`。

## 迁移和验证

`python-agent/migrations/012_article_revisions.sql` 添加两个版本指针和两张表。执行现有迁移入口可重复运行，历史文章按需补快照，不批量复制全部正文。

```powershell
cd python-agent
.venv\Scripts\python.exe -m app.migrate
.venv\Scripts\python.exe ..\scripts\article-review-check.py
```

专项脚本使用本地临时账号、分类和文章，检查权限隔离、首次审核、驳回、撤回、版本恢复、旧版公开、计数、审核轨迹、索引事件、旧文章兼容、校验值、软删除、并发编辑及审核/撤回竞争。结束后清理临时数据，JSON 报告保存在 `logs/evaluation`。`--preview` 需在交互终端运行，用于保留临时账号进行页面验证。
